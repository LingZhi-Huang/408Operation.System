## 4.1 文件与文件系统基本概念

### 4.1.1 文件是什么

**【比喻】** 你打开电脑找"期末论文.docx"，只需要说出文件名；至于它在磁盘第几号扇区，你根本不关心，也不需要关心。**文件就是操作系统替你保管的、有名字的一组相关信息**。

**定义**：

> **文件**（File）：具有文件名的一组相关信息的集合，以文件名为接口，**按名存取**，存储在**外存**上，读写以**块（扇区）**为单位。

三个关键点，考试常从这三句话出题：

1. **按名存取**：用户只跟文件名打交道，物理位置由操作系统管理（这正是文件系统存在的意义）；
2. **存储在外存**：磁盘、磁带等 **I/O 设备本身也可看作特殊的文件**；
3. **读写以块为单位**：虽然用户眼中文件是一串字符/记录，但操作系统底层总是按**逻辑块**读入一块再切给用户。

**【考点】** "文件是相关信息的集合" + "按名存取" 是概念题常考的两个关键词，选择题直接选。

### 4.1.2 文件的常用属性

一个文件的"户口本"上要登记这些信息：

| 属性 | 含义 | 备注 |
| --- | --- | --- |
| 名称 | 用户看到的文件名 | 按名存取的依据 |
| 标识符 | 系统内部的唯一编号 | 与名称无关，系统只认编号 |
| 类型 | 普通文件 / 目录文件 / 设备文件（字符/块设备） | 支持不同类型的操作 |
| 位置 | 指向物理盘块的指针 | FCB 中最核心的字段 |
| 大小 | 当前文件长度（字节数/块数） | 动态增长 |
| 保护 | 读 / 写 / 执行权限、属主 | 4.6 节展开 |
| 时间 | 创建 / 修改 / 访问时间 | 备份与审计用 |

### 4.1.3 文件的基本操作：创建、删除、打开、关闭、读、写

**【考点】系统调用与引用的完整生命周期**，最常考的是 **open 与 close 的"引用计数"**。

![文件、FCB与基本操作](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-01_file_basics.png)

*图4-2 文件、FCB与基本操作：左——文件的定义与属性；中——FCB 的内容；下——六种基本操作流程；右上——打开文件表与引用计数机制*

**① 创建文件（create）**
1. 申请一个 **FCB（文件控制块）**；
2. 在磁盘**空闲空间**中为文件分配数据块（或预留）；
3. 把 FCB 与文件名登记到**目录**中。

**② 删除文件（delete）**
1. 从目录中**删除目录项 / FCB**；
2. 把该文件占用的**数据块全部归还**给空闲空间管理结构（空闲表/位示图/成组链接等）；
3. （共享文件要等链接计数减到 0 才真正删除，见 4.5 节。）

**③ 打开文件（open）——重点！**

> **open 的本意**：把文件的**目录项（FCB）信息从磁盘调入内存**，在内存中建立（或找到）一条**打开文件表项**，并把表项地址（文件描述符 fd）返回给用户。**open ≠ 读出数据。**

为什么操作系统要搞"打开"这一步？因为**每次读写都去查一遍目录太慢了**。目录表可能很大、在磁盘上，每次按名检索都是一次漫长的 I/O。于是：

- 第一次 open(file)：检索目录 → 把 FCB 调入内存 → 建立打开文件表项（记下读/写指针、文件号、引用计数等）；
- 第二次、第三次……（同一文件被多个进程打开）：**不再检索目录**，直接查内存中的打开文件表，把该表项的**引用计数 +1**；
- close(file)：引用计数 **−1**；计数减到 **0** 时，才真正撤销该打开文件表项。

**【看图抓手】** 上图右上：进程 P1、P2 同时打开同一文件 → 打开文件表中该项的引用计数 = 2，close 时共享减一。

**④ 关闭文件（close）**：撤销打开文件表项（或减计数）；系统强制写回缓冲区中的修改内容。

**⑤ 读文件（read）/ 写文件（write）**：系统调用参数是**文件描述符 fd + 缓冲区指针 + 长度**，而不是文件名——因为文件已被"打开"，系统知道到哪去找它。

**【易错】** 打开与关闭是"内存里的登记与注销"，创建与删除才是"磁盘上的生与死"。**四个动作两两正交**，选择题最爱混淆。

> 【记忆口诀】**先开后读、各算各（计数）**：读前必先打开；引用计数"多开 +1、关闭 −1、归零注销"。

#### 深化学习：open() 的内幕——两级打开文件表

![4-19 打开文件表与fd](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-18_open_file_tables.png)

*图4-19 open() 的内幕：进程 fd 表 → 系统级打开文件表 → 磁盘 FCB。open 返回的 fd 只是"进程表里的槽号"。*

**图后解读要点**：

- **为什么设计两级**：系统级表存放 FCB 副本与**引用计数**（几个进程打开了它）；进程级 fd 表只存"槽号 → 系统表条目"的指针——父子进程 fork 后共享系统表条目，**读写指针也是共享的**（父进程读完子进程接着读，指针不会互相覆盖）；
- **open 的收益**：按名检索目录要多次读盘，代价高；打开一次后，后续 read/write **只凭 fd 直接定位**，不再碰目录；
- 【易错】"close 会把文件从磁盘删除" → **错**！close 只把引用计数 −1，计数归 0 才释放系统表条目；删除文件用的是 delete。

## 4.2 文件的逻辑结构

**逻辑结构** = 站在用户/程序角度，文件里的记录怎么组织。与此相对，**物理结构**（4.3 节）是站在磁盘角度，文件块怎么摆放。

任何一个文件都可以看成是**记录（record）的序列**（记录 = 一组信息项的集合，如"学号+姓名+成绩"一行）。按记录的组织方式，逻辑结构分四类。

### 4.2.1 顺序文件

**定义**：文件中的记录**一个接一个地存放**，顺序排列。

| 分类 | 特点 | 访问方式 | 查找/增删效率 |
| --- | --- | --- | --- |
| **串结构** | 记录按**写入顺序**自然排列 | 顺序存取 | 查找需从头找；增删在末尾 O(1) |
| **顺序结构** | 记录按**关键字对文件排序** | 顺序 + 随机（可折半查找） | 查找快；但增删要维持有序，需移动记录 |

还可以按记录长度分：

- **定长顺序文件**：每条记录等长 L。第 i 条记录的地址 = 首地址 + (i-1)× L ——**一个公式直接算出地址，支持随机存取**。
- **变长顺序文件**：记录长度不固定，**无法由公式定位**，第 i 条必须要从头扫过前 i-1 条，**只能顺序存取**；删除记录后还要移动/重写大量数据。

![文件的逻辑结构](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-02_logical_structures.png)

*图4-3 文件逻辑结构四连：定长顺序文件（可随机定位）→ 变长顺序文件（只能顺序）→ 索引文件 → 索引顺序文件（N 条记录分 √N 组）*

**【考点】** "定长记录文件才能随机存取"+"变长文件只能用顺序存取、查找慢"——几乎每年都有一道选择题在绕这个点。

### 4.2.2 索引文件

**问题**：变长顺序文件查找太慢，怎么办？——**给它做一本"目录册"**。

**索引文件** = 数据区（变长记录，随便排）+ **索引表**（每条记录一行：关键字、逻辑长度、物理地址）。

- 索引表**按关键字排序** → 可以**折半查找**，检索速度从 O(N) 降到 O(logN)；
- **增删记录只需修改索引表**，不用搬动数据区的数据；
- 代价：索引表本身占用额外空间。

### 4.2.3 索引顺序文件（本章第一个"数字题"来源）

**问题**：一个文件有 N 条记录，建了索引是快了，但每条记录都建索引太占空间。折中方案：

> **索引顺序文件**：把 N 条记录**分成 √N 组**，每组内部记录保持有序（组内无索引），再为**每组**建立一条索引（索引表每项 = 该组的最大关键字 + 起始地址）。

**查找次数分析（必掌握）**：
- 纯顺序文件：平均需要比较 **N/2 次**；
- 索引顺序文件：先查索引表（√N 项，平均 √N/2 次），再组内顺序找（√N 条，平均 √N/2 次），总平均 ≈ **√N/2 + √N/2 = √N 次**。

**【真题风格例题】** 某索引顺序文件有 **100 条记录**，如何组织最快？

**解**：设分成 a 组、每组 b 条，则 a × b = 100。平均查找次数 ≈ a/2 + b/2，由均值不等式，a=b=√100=10 时最小。即**10 组 × 每组 10 条**：先查索引表平均 5 次，再组内平均 5 次，**共约 10 次**；而纯顺序查找平均要 50 次。查找速度提高约 5 倍。

**【考点】** 分组数 = 每条记录数 = √N，使 a/2+b/2 最小化为 √N。数值例子好背：N=100 → 10 组×10 条 → 平均约 10 次比较。

#### 深化学习：索引文件如何给变长记录"提速"

![4-20 索引文件查找示意](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-19_index_file_access.png)

*图4-20 索引文件：主文件仍是变长记录，但另建一张定长、按关键字排序的索引表——顺序查找升级为二分查找。*

**图后解读要点**：

- **算一笔账**：10^6 条记录，顺序查找平均 5×10^5 次比较；索引表排序后**二分查找只要约 20 次**（log2(10^6)）——这就是"索引"二字的含金量；
- **索引表为什么定长？** 每项只存（关键字 + 指针），与记录本身长度无关——变长的难题被转移到了"指针所指的位置"；
- 【对比记忆】顺序文件（定长可随机/变长只能顺序）→ 索引文件（变长也能快查）→ 索引顺序文件（分组 √N，再省一层）——三者是检索效率的三级跳。

### 4.2.4 无结构文件（流式文件）

文件被看作**一串字符流**（如源代码文件、音频文件），没有记录的概念，由程序自己解释。早期操作系统还区分"记录式文件/流式文件"，408 考纲下只需知道：**无结构文件 = 字符流**，典型如 linux 中默认的普通文本文件。

## 4.3 文件的物理结构 / 分配方式（本章最重点 ★★★★★）

**物理结构** = 磁盘上文件的数据块怎么**分散**地摆。四种分配方式：**连续分配、隐式链接、显式链接（FAT）、索引分配**。

> 先建立三个评价维度（考研对每种结构都从这三方面考）：
> ① **能否随机访问**（读第 i 块要几次访盘？）；
> ② **扩展难不难**（文件后面加数据是否方便）；
> ③ **空间浪费**（外部碎片？指针占用？索引额外空间？）。

### 4.3.1 连续分配

**【比喻】** 图书馆把一套书**整整齐齐排在一个连片书架上**，书目卡上写"从第 3 格开始，占 5 格"。

![连续分配](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-03_physical_continuous.png)

*图4-4 连续分配：文件 A 占据物理块 3~7（连续），文件 B 占据块 10~12；其余块号 8、9、13、14、15 是零散的空闲块=外部碎片*

**原理**：为文件分配**一组相邻的物理盘块**；目录项（FCB）只需记录**（起始块号，文件长度）**。

**核心公式**：物理块号 = 起始块号 + 逻辑块号 → **读第 i 块只需 1 次访盘**，直接定位（O(1)）。

**优点**：① 顺序存取快（磁头按物理顺序移动）；② 随机存取也快（公式定位）；③ 目录结构简单。

**缺点**：① **文件扩展难**——文件后面可能已被别的文件占住，只能整体搬移（或预留空间）；② **外部碎片**——空闲块零散不成片，大文件无法利用；③ 要定期**紧凑化**（复制整个文件，代价大）。

**【易错·外部碎片 vs 内部碎片】**
- **外部碎片**：空闲块散落在已分配块之间，数量够但**不连续**，无法满足连续分配——连续分配的病；
- **内部碎片**：块内剩余空间（如文件只有 2.5KB 却占一个 4KB 块，浪费 1.5KB）——**所有按块分配方式的通病**，但不是连续分配特有的缺点。

**适用**：系统文件、交换区（swap）、顺序写入且不常修改的文件。

> 【考点】连续分配对**可增长性**与**碎片**的考查最多。"文件在创建时就要规定最大长度（否则扩展难）"是连续分配的典型特征。

### 4.3.2 隐式链接（链接分配）

**【比喻】** 散架的书页，每页背面写着"下一页在哪一格"，最后一页写着"下一页没有了"。找第 10 页？必须从第 1 页翻起，一页一页顺着找。

![隐式链接与显式链接FAT](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-04_physical_linked.png)

*图4-5 左：隐式链接——指针存在每个数据块内部（块3→5→12→8→NULL）；右：显式链接——指针集中到 FAT 表中，FAT 整表常驻内存*

**隐式链接原理**：每个数据块的**尾部**多存 4B，记录**下一个物理块的块号**；链尾块存 NULL。目录项只记**首块号（+块数）**。

**致命的缺点——不能随机访问**：读第 i 块，必须从首块开始，**一块一块读出指针**，读第 i 块需要 **i 次访盘**！

【考点】这个 "i 次" 是高频结论，结合 4.3.5 的对比图记住。

其他缺点：① 指针占块内空间（每块尾部 4B，内部碎片增大）；② **坏一块 → 断链**，其后数据全部丢失（只能从头重建）；③ 只能顺序存取。
优点：① 无外部碎片；② 扩展容易（链尾追加一块即可）。

### 4.3.3 显式链接（FAT——File Allocation Table）

**【比喻】** 把每页背面"下一页在哪"的答案全部抄到**一张总表格**上，这张表格（文件分配表 FAT）**一直放在内存里**。

| 块号 | 3 | 5 | 12 | 8 | …… |
| --- | --- | --- | --- | --- | --- |
| 下一块号 | 5 | 12 | 8 | EOF | …… |

**原理**：整张 **FAT 表（块号 → 下一块号）作为文件系统的一部分常驻内存**。逻辑块号 i → 在 FAT 表中查 ARRAY[i] → 直接得到**物理块号**。

**为什么读任意一块只需 1 次访盘？**

> 查 FAT 表 = 查内存数组（O(1)，**不需要访盘**）；拿到物理块号后，**再读一次盘**拿到数据。所以读第 i 块 = **1 次访盘**。这就是"FAT 用内存换时间"。

**【考点】FAT 的两个典型数字题方向**
1. **访盘次数**：显式链接读任意块 **1 次**（与连续分配相同），这是它与隐式链接的本质区别；
2. **FAT 自身占多大空间**：FAT 表项数 = 磁盘总块数；表项大小 = 一个块号需要的位数（通常 4B）。
   例：磁盘 800MB、块 4KB → 共有 800MB/4KB = 200K 块 → FAT 表项数 200K，每项 4B → **FAT 约 0.8MB**，约占磁盘 0.1%。代价可控。

**缺点**：① FAT 占用额外磁盘空间；② **FAT 一旦损坏，所有文件的链都断了**（全盘数据无法寻址），所以 FAT 通常保留多份备份。

**适用**：Windows 的 FAT32/exFAT 就是显式链接的代表；块小、文件多的系统适合。

> 【记忆口诀】**连续占座、隐式接龙、FAT 查表**：FAT 是"把链表的指针抄到内存里"，所以链表的缺点（不能随机）被治愈，代价是 FAT 的额外空间。

#### 深化学习：FAT 读第 i 块的完整走位

![4-22 FAT查表走位](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-21_fat_walkthrough.png)

*图4-22 FAT 查表走位：读逻辑第 3 块 = 在内存的 FAT 里跳 3 次（块2→块5→块7）+ 最后 1 次读盘取数 = 1 次访盘。*

**图后解读要点**：

- **关键在"链搬进了内存"**：隐式链接的指针藏在数据块里，想找下一块必须先把当前块**读盘**；FAT 把所有"下一块"信息集中到一张常驻内存的表里——**跳链不花 I/O**；
- **FAT 的代价定量看**：100GB 磁盘、块 4KB → FAT 有 2500 万项 × 4B ≈ **100MB** 内存——块越小 FAT 越肥，这就是 FAT32 支持的最大分区受限的原因之一；
- 【易错】"FAT 方式读第 i 块需要 i 次访盘" → **错**（i 次查表在内存完成，访盘只有 1 次）；"隐式链接读第 i 块需 i 次访盘" → **对**（逐块读盘顺链爬）。

### 4.3.4 索引分配

**【比喻】** 每本书配一本**"目录小册子"**：小册子第 k 页记录这本书第 k 部分在第几格。找书第 k 部分：先翻小册子（1 次访盘），再到对应格子取（1 次访盘）。

![索引分配](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-05_physical_index.png)

*图4-6 索引分配：FCB→索引块（存放所有数据块号）→数据块；下方三种"索引块装不下"的改进：链接方案、多层索引、混合索引*

**原理**：为**每个文件**建立一个**索引块**，索引块中存放该文件**全部数据块的块号**。FCB 中记录**索引块号**。

- **优点**：① 支持**随机访问**（读索引块 1 次 + 读数据块 1 次 = **2 次访盘**；若索引块常驻内存则 1 次）；② 无外部碎片；③ 文件可动态增长。
- **缺点**：① 每个文件都吃一个索引块，**小文件浪费**；② 大文件时**一个索引块装不下**（如块 4KB、块号 4B → 一个索引块只装 1024 个块号）。

**索引块装不下怎么办？——三种改进方案**

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **链接方案** | 索引块自身串成链（索引块1→索引块2…） | 无连续要求 | 找第 i 块需沿链找，慢 |
| **多层索引** | 一级索引指向二级索引，逐层展开 | 容量指数增长 | 小文件也要逐层读，开销大 |
| **混合索引** | 直接地址 + 一级 + 二级 + 三级间接 | 小文件用直接区、大文件逐级展开，兼顾两者 | 实现最复杂（UNIX 方案） |

#### 深化学习：多层索引的算账模板

![4-21 多层索引计算模板](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-20_multilevel_index_calc.png)

*图4-21 多层索引算账：每块 4KB、地址 4B → 每个索引块 1024 项；每升一级容量 ×1024、读盘次数 +1。*

**图后解读要点**：

- **记一个"杠杆比"**：4KB/4B = 1024 = 2^10 —— 多级索引每加一层，可寻址大小放大约 1000 倍、访盘次数加 1；
- **通用公式**：N 级索引最大寻址 = (块大小/地址大小)^N × 块大小；读数据访盘 = N+1 次（索引块 N 次 + 数据块 1 次）；
- 【自测】块 1KB、地址 4B → 每块 256 项；两级索引最大文件 = 256² × 1KB = **64MB**，读一块访盘 **3** 次。

### 4.3.5 【必做例题】UNIX 混合索引（本章第一计算题，请自行验算）

**题目**：UNIX 文件系统采用混合索引。已知**块大小 4KB，块地址 4B**。问：

1. 每个索引块中能装多少个块号？
2. 最大文件长度是多少？
3. 假设 inode 已在内存（索引块均未在内存），读文件的直接区、一级间接区、二级间接区、三级间接区的任意一块，各需几次访盘？
4. 若文件长度恰好为 5MB，读其最后一块需要几次访盘？

![UNIX混合索引](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-06_unix_mixed.png)

*图4-7 UNIX 混合索引：inode 内含 10 个直接地址 + 3 个间接指针（一级/二级/三级），间接指针逐层指向索引块树，各层容量 40KB / 4MB / 4GB / 4TB*

**解**：

**① 每索引块块号数**：4KB ÷ 4B = 1024 项。

**② 容量逐层算**：

| 层次 | 计算 | 容量 |
| --- | --- | --- |
| 10 个直接地址 | 10 × 4KB | **40 KB** |
| 一级间接 | 1024 × 4KB | **4 MB** |
| 二级间接 | 1024 × 1024 × 4KB | **4 GB** |
| 三级间接 | 1024 × 1024 × 1024 × 4KB | **4 TB** |
| **最大文件** | 40KB + 4MB + 4GB + 4TB | **≈ 4.008 TB** |

**③ 访盘次数**（假设：**inode 在内存；各级索引块都不在内存**）：

- 直接区：1 次（直接地址在内存 inode 中，直接读数据块）；
- 一级间接区：读一级索引块（1 次）+ 读数据块（1 次）= **2 次**；
- 二级间接区：读一级索引块（1）+ 读二级索引块（1）+ 读数据块（1）= **3 次**；
- 三级间接区：**4 次**。

> **【考点】** 若题目说"索引块已在内存"，则各级都要减去读索引块的次数——直接区 1 次、一级 1 次、二级 2 次、三级 3 次。**答题时务必写明假设**。

**④ 读 5MB 文件的最后一块**：

- 逻辑块号 = 5MB / 4KB = 1280 块（第 0 块到第 1279 块）；
- 直接区覆盖逻辑块 0~9（10 块）；一级间接区覆盖 10~1033（1024 块）；二级间接区覆盖 1034~1049609（1024×1024 块）；
- 最后一块是第 1279 块，落在**二级间接区**（1034 ≤ 1279 ≤ 1049609）；
- 1279 块在二级间接区内的位置：1279 - 1034 = 245，需读出二级索引块的第 245 项；
- 访盘次数 = **3 次**（一级索引块 + 二级索引块 + 数据块，且 1279 若恰好落在索引块边界也不用多读）。

**⑤ 常见追问**：逻辑块号 100 在第几级？→ 100 > 9 且 100 ≤ 1033 → **一级间接区**，读其块需 **2 次访盘**。

#### 专项训练：给偏移量，判区间、算访盘

![4-29 UNIX混合索引区间练习](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-28_unix_index_calc.png)

*图4-29 UNIX 混合索引区间对照表：偏移 → 逻辑块号 → 落在哪一区 → 访盘次数（inode 已在内存的口径）。*

**训练模板（四步）**：

1. **偏移 → 逻辑块号**：块号 = 偏移 div 4096；
2. **判区间**：块号 <10 直接区；<10+1024 一级间接；<10+1024+1024² 二级间接；再往上三级；
3. **换算区内序号**：一级间接要减去直接块数 10（如逻辑块 1280 → 一级区内第 1270 项）；
4. **数访盘**：直接 1 次、一级 2 次、二级 3 次、三级 4 次。

**自测一题**：读偏移 4MB+5000 字节处的数据要几次访盘？
**解**：(4MB+5000) div 4096 = 1024+1 = 1025 号逻辑块；1025−10 = 1015 < 1024 → **一级间接区 → 2 次访盘**。

### 4.3.6 【必做对比】同一场景"读第 i 块"：四种结构各几次访盘？

![各物理结构访盘次数对比](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-07_access_compare.png)

*图4-8 同一场景"读文件的第 i 块"：连续分配 1 次；隐式链接 i 次；显式链接 FAT 1 次；单级索引 2 次（索引块未在内存时）*

**全对比大表（背下来）**：

| 结构 | 随机访问 | 读第 i 块访盘次数 | 顺序存取 | 额外空间 | 扩展 | 主要缺点 | 适用 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **连续分配** | √ 支持 | **1 次** | 快（磁头顺序移动） | 无 | 难（整体搬移/预留） | **外部碎片、扩展难** | 系统文件、少修改文件 |
| **隐式链接** | × 不支持 | **i 次** | 慢（沿链前进） | 块内 4B 指针 | 容易（链尾加块） | 不能随机、断链风险 | 一次写多次顺序读 |
| **显式链接 FAT** | √ 支持 | **1 次** | 快 | 整张 FAT 表（约 0.1% 容量） | 容易 | FAT 占用与损坏 | FAT 类文件系统 |
| **单级索引** | √ 支持 | **2 次**（索引块未在内存） | 快 | 每个文件一个索引块 | 容易 | 小文件浪费、大块数装不下 | UNIX/现代文件系统 |

> 【记忆口诀】**连续一笔、隐式排队、FAT 查表、索引查库**：连续和 FAT 都是 1 次访盘读到数据；隐式链接第 i 块要 i 次；单级索引 2 次。

## 4.4 文件目录

### 4.4.1 目录管理要解决什么

**【比喻】** 图书馆没有目录卡片会怎样？你只能记住"我要找的那本书在第 3 排第 5 架第 2 层"——一旦书挪了位置你就找不到了。**目录（directory）就是按名找到文件的"检索表"。**

**目录管理的要求**（考试原话，三件事）：

1. **按名存取**：用户给出文件名，系统返回文件（的核心指标：**检索效率**）；
2. **高效检索**：怎么让"查名字"的动作少读几次盘；
3. **支持文件共享**（多个用户共用同一个文件）。

### 4.4.2 FCB：文件控制块

**FCB（File Control Block，文件控制块）** = 一个文件的管理信息集合，**文件存在的唯一标志**。从逻辑上讲：

> **目录 = 一组 FCB 的有序集合**；目录是一个"特殊文件"，内容就是一张张 FCB（或目录项）。

FCB 里装什么？——还记得 4.1 节的"文件属性"吗？FCB 就是把这些属性**存下来的地方**：文件名、类型、物理位置（起始块号/索引块号）、大小、存取权限、时间等。**其中"物理位置"是灵魂**：文件系统靠它把逻辑文件对应到盘块。

### 4.4.3 索引结点 inode：给目录项"瘦身"

**【问题】** 传统目录项 = 完整 FCB（约 64B）。目录文件里全是这些"大块头"目录项：磁盘块 1KB 只能装 **16 个目录项**。要找到一个文件，需要读很多目录块——**每次检索都是一串 I/O，慢**。

**【Solution：把 FCB 拆分】**

- **磁盘索引结点（inode）**：存放与文件**检索关系不大**的"大件"信息——**链接计数、属主 ID、存取权限、时间戳、数据块指针**等；
- **目录项瘦身**：只保留 **文件名（约 8B）+ inode 号（4B）≈ 12B**；
- **目录文件** = 一排 12B 的短小目录项；**inode 表**单独存在磁盘上，按 inode 号直接索引。

![FCB与索引结点](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-09_inode.png)

*图4-9 FCB 与索引结点：左——传统目录项=完整 FCB（1KB/块≈16 项）；右——目录项瘦身只存文件名+inode 号（1KB/块≈85 项），其余信息拆分到 inode 表*

**效率对比（例题式演算）**：

| | 传统目录项 | inode 方案目录项 |
| --- | --- | --- |
| 目录项大小 | ≈ 64B | ≈ 12B |
| 1KB 磁盘块容纳目录项数 | 1024 ÷ 64 = **16 个** | 1024 ÷ 12 ≈ **85 个** |
| 检索一个目录块（1KB）| 一次性读入 16 项 | 一次性读入 85 项，**同样 I/O 找到名的概率高 5 倍** |

> **结论**：瘦身把每块可容纳的目录项数从 16 变到 85，**检索目录的 I/O 次数大幅减少**——这是 inode 存在的第一理由。

**【考点·为什么文件名不进 inode？】** 文件名是**目录项**的内容，不是文件本身的内容。多个目录项可以指向**同一个 inode**（这就是硬链接，见 4.5 节）；如果 inode 里存了文件名，就会出现"一个文件有两个名字"的矛盾。所以：**inode 管数据与管理信息，文件名只在目录里。**

> 【记忆口诀】**名字留在门口（目录），身契收进档案（inode）。**

### 4.4.4 目录结构的演进：单级 → 两级 → 树形 → 无环图

![目录结构演进](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-08_directory_evolution.png)

*图4-10 目录结构四连：单级（无法重名）→ 两级（MFD+UFD，解决隔离）→ 树形（绝对/相对路径）→ 无环图（共享，配合链接计数）*

**① 单级目录结构**：全部文件的目录项放在**一个目录**里。

| 优点 | 缺点 |
| --- | --- |
| 结构最简单 | ① **重名冲突**（A 的用户和 B 的用户都叫"作业.doc"）；② 检索慢（一个目录=一个大数组）；③ 所有用户文件混在一起，保护困难 |

只适用于单用户单任务系统（如早期 DOS 简化场景）。

**② 两级目录结构**：**主文件目录 MFD**（按用户名登记）+ **用户文件目录 UFD**（每个用户一个子目录）。

- 优点：**解决重名**——不同用户的 UFD 互相独立，都叫"作业.doc"也没问题；还能按用户分组实施保护。
- 缺点：**不能给用户之间共享文件**（文件藏在某个 UFD 里，别人看不见）。

**③ 树形目录结构**（现代操作系统标准）：任何一层目录下可再有子目录，**树形**（无环）。

- 绝对路径：从根开始的一串名字，如 `/usr/user1/作业.txt`；
- 相对路径：从**当前目录**开始，如 `user1/作业.txt`；
- 优点：**层次清晰、便于分类、便于管理和保护**；
- 缺点：**不便于实现共享**——A 想把文件共享给 B，B 只能沿 A 的路径去访问，路径又长又麻烦（要引入"链接"）。

**④ 无环图目录结构**：允许**多个目录项指向同一个文件/子目录**，但要**禁止环**（否则循环查找）→ 构成"无环图"。

- 实现共享的方式：给文件设置**共享计数器（链接计数）**；
- **删除语义（重要考点）**：删除只是把该目录项删掉、**计数 −1**；**只有计数减到 0 才真正删除文件**（释放 inode 与数据块）；
- 优点：方便共享；缺点：管理复杂（要防环、维护计数）。

**【易错】** 树形目录**不能用"共享"**，无环图/链接才能共享——选择题最喜欢把"树形目录支持共享"写成正确选项来误导。

#### 深化学习：绝对路径与相对路径的检索成本

![4-23 目录树与路径](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-22_dir_tree_paths.png)

*图4-23 树形目录：绝对路径 /home/levi/notes.md 从根逐级检索；设了当前目录 /home/levi 后，相对路径 notes.md 只查一级。*

**图后解读要点**：

- **路径长度 = 检索目录的次数**：绝对路径 3 级 → 至少读 3 个目录文件（多次访盘）；当前目录机制把起点"空降"到半路，剩下 1 级——这就是"设置当前目录可加快文件检索"的原理；
- **每个目录也是文件**：目录文件的内容是一张"目录项表"，检索 = 把目录文件读入内存逐项比对文件名——所以目录项越小（inode 瘦身），一个磁盘块能装的目录项越多、读盘次数越少；
- 【易错】"引入当前目录后，所有文件的检索都不再需要从根开始" → **错**（不在当前目录子树下的文件仍要回根，或用 .. 逐级上行）。

### 4.4.5 目录项（目录条目）的基本操作

一个目录中，对目录项的经典操作（了解即可）：**查找**（按名检索，最核心）、**创建**（建新目录项）、**删除**、**改名**、**遍历**（ls/列出目录）。

## 4.5 文件共享

**文件的共享** = 多个用户（或多个目录项）共用同一个文件。两种经典实现：**硬链接**与**软链接（符号链接）**。

### 4.5.1 硬链接（Hard Link）

**【比喻】** 同一个人的**两张身份证**：名字不同（file1、file2），但后面都是同一个"人"（inode）。人活着，两张证都有效；人死了，证全作废。

![硬链接vs软链接](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-10_hard_soft_link.png)

*图4-11 左：硬链接——file1、file2 两个目录项指向同一 inode（链接计数=2）；右：软链接——link1 是独立小文件，内容是目标路径，目标删除后悬空*

**原理**：两个（或多个）目录项**指向同一个 inode 号**；inode 中**链接计数（nlink）记录有多少个目录项指向它**。

- `ln file1 file2`：新建目录项 file2 → 计数 2；
- `rm file1`：计数 2→1，**数据还在**；
- `rm file2`：计数 1→0，**真正的删除**（释放 inode + 全部数据块）。

**硬链接的两个限制（必考）**：

1. **不能跨文件系统**：inode 号**只在同一个文件系统/分区内有意义**，另一个文件系统的 inode 表中同样的编号是另一个文件！
2. **不能给目录建立硬链接**：否则目录树会成环（经典的"循环查找"灾难）。

**优点**：实现简单、**不占额外空间**、访问快（直接按 inode 找，不多读一次盘）。

### 4.5.2 软链接（符号链接，Symbolic Link）

**【比喻】** 宾馆前台留了一张纸条："307 房客的行李放 402 房"（纸条=软链接，行李=文件）。行李搬走了，纸条还在——**悬空链接**；你去 402 只能扑空。

**原理**：软链接是一个**真正的独立小文件**，有自己的 inode 和数据块，数据块里存的内容**只是目标文件的路径字符串**（如 `/usr/u/file1`）。

- `ln -s file1 link1`：创建 link1，内容是 `file1` 的路径；
- 访问 link1：**① 读 link1 的数据块，取出路径 → ② 按路径检索目录，再读目标文件的数据块** → **比直接访问多 1 次访盘**；
- `rm file1`：inode A 与数据块被释放，**link1 还在**（它自己有 inode），但内容（路径）已指向不再存在的文件 → **悬空链接**，访问报错 "No such file or directory"。

**软链接的优点**：① 可**跨文件系统**（存的是路径，跟 inode 无关）；② 可**链接目录**（目录的"快捷方式"）。

**软链接的缺点**：① 访问多读一次盘；② 目标文件删除后**悬空**（硬链接没有这个问题——只要计数大于 0，数据就还在）。

### 4.5.3 硬链接 vs 软链接对比表（必背）

| 对比项 | 硬链接 | 软链接（符号链接） |
| --- | --- | --- |
| 本质 | 目录项指向同一 **inode** | 独立小文件，**内容是路径字符串** |
| 链接计数 | inode 中计数 **+1** | 目标文件 inode 计数**不变**（link1 有自己的 inode） |
| 删除目标文件后 | 另一目录项仍可用（计数 ≥1） | **悬空链接**（路径失效） |
| 访问开销 | 与正常访问相同 | **多 1 次访盘**（读链接文件取路径） |
| 跨文件系统 | **不能** | **能** |
| 链接目录 | **不能**（防环） | **能**（快捷方式） |
| 额外空间 | 无（只加一个目录项） | 链接文件本身占 inode + 数据块 |

> 【记忆口诀】**硬链接认人（inode）、软链接认路（路径）**：认人的不能跨家（文件系统）扯证；认路的可以到处指，但路塌了（目标删除）就悬空。

**【真题风格例题】** 文件 F 有 nlink=2（fileA、fileB 两个目录项）。执行 `rm fileA` 后 nlink=？文件数据是否释放？再执行 `ln -s fileB soft`、`rm fileB` 后 `cat soft` 能否成功？

**答**：
1. `rm fileA`：nlink 2→1，数据**未释放**；
2. `ln -s fileB soft`：**nlink 不变**（软链接不增加计数），soft 的内容是 `fileB` 路径；
3. `rm fileB`：nlink 1→0，**数据真正释放**；
4. `cat soft`：**失败**——soft 的内容（路径 fileB）已经指向不存在的文件，报错。这就是"软链接悬空"。对照：若步骤 2 换成硬链接 `ln fileB hard`，nlink 变 3，`rm fileB` 后 nlink=2≠0，hard 依然能读。

## 4.6 文件保护

三个层次（由弱到强、考点密集）：

### 4.6.1 口令

- 创建文件时设置**口令**（密码），访问时验证；
- 优点：实现简单，占空间小（口令存在 FCB 中）；
- 缺点：① 口令存在系统的 **FCB 中**，**系统管理员/窃取者可以读到**；② 一个文件一个口令，口令多了记不住；③ 每次访问都要输口令，麻烦。

### 4.6.2 加密

- 文件内容**加密存储**（明文→密文），用户口令作**密钥**解密；
- 优点：**安全性最高**：即使**文件内容泄露或读到磁盘原始数据，没有密钥也无法解读**；
- 缺点：加密/解密要**付出时间代价**；口令丢失 = 数据永久无法恢复。

> 【考点】口令保护的是"访问资格"，加密保护的是"内容本身"。选择题：哪个能防止数据被读到后仍然泄密？——**加密**。

### 4.6.3 访问控制

**访问控制矩阵**（二维表，行=用户，列=文件，格=权限）：

- 按**列**存储 → **访问控制列表 ACL（Access Control List）**：每个文件后挂一张表"谁能怎么访问"；
- 按**行**存储 → **能力表（Capability List）**：每个用户后挂一张表"我能访问什么"。

| 矩阵按列存 | ACL 访问控制列表 | 每个文件后面：张三（读/写）、李四（只读）…… |
| --- | --- | --- |
| 矩阵按行存 | 能力表 | 每个用户后面：a.txt（读/写）、b.txt（只读）…… |

学习时请提一下 **Linux 的 rwx**：属主（user）/组（group）/其他（other）各 3 位，如 `rw-r--r--`：属主可读写、组与其他人只读。目录的 x 表示"可进入该目录"。

> 【记忆口诀】**列放门口叫 ACK（ACL）、行装口袋叫能力（Capability）。**

#### 深化学习：一张矩阵看懂 ACL 与能力表

![4-24 访问控制矩阵与ACL能力表](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-23_acl_matrix.png)

*图4-24 访问控制矩阵按列切 = ACL（挂在每个文件上：谁能动我）；按行切 = 能力表（每个用户一份：我能动谁）。*

**图后解读要点**：

- **实际系统为什么不用整张矩阵**：矩阵太大且极稀疏（绝大多数用户对绝大多数文件无权限）——所以按"列"或按"行"切开只存非空项；
- **两种切的适用场景**：服务器管理员问"这个文件谁能碰？"（按文件查 → ACL）；进程运行时问"我能不能碰它？"（按主体查 → 能力表，持有能力凭证即可访问，无需再查全局）；
- 【易错】"能力表是按文件（对象）存储的" → **错**，能力表按**用户（行）**存；"ACL 挂在用户身上" → **错**，ACL 挂在**文件**上。

## 4.7 文件系统的层次结构

**【考点】功能归属题**：把某个功能（如"把逻辑块号转换为物理块号"）放到正确的层，是每年的吃分点。七层自上而下：

![文件系统层次结构](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-11_fs_layers.png)

*图4-12 文件系统层次结构：用户接口 → 文件目录系统 → 存取控制模块 → 逻辑文件系统与文件信息缓冲区 → 物理文件系统 → 辅助分配模块/设备管理程序 → 物理设备；右侧为"读文件第 3 块"逐层向下的处理路径*

| 层（自上而下） | 主要职责 | "读文件第 3 块"中该层干的事 |
| --- | --- | --- |
| ① 用户接口 | open/read/write/close 等系统调用 | 用户提出 read(fd, 缓冲区, 第 3 块) |
| ② 文件目录系统 | **按名存取**：查目录、找 FCB | 按文件名查目录，找到 FCB（得到逻辑块号信息） |
| ③ 存取控制模块 | **权限验证** | 校验读权限，非法则拒绝访问 |
| ④ 逻辑文件系统与文件信息缓冲区 | **逻辑块号 → 物理块号**；文件信息缓冲区 | 把逻辑块号 3 换算成物理块号 |
| ⑤ 物理文件系统 | **物理块号 → 物理设备地址（柱面:盘面:扇区）**；分配/回收盘块 | 转换成磁盘设备地址 |
| ⑥ 辅助分配模块 / 设备管理程序 | 空闲盘块分配回收；**磁盘驱动（含磁盘调度）** | 组装 I/O 请求、调度磁盘、启动传输 |
| ⑦ 物理设备 | 磁盘等外存硬件 | 机械动作完成传输 |

> **【考点·标准答案】** 按王道教材表述：
> - "**将文件的逻辑块号转换为物理块号**" 属于 **逻辑文件系统与文件信息缓冲区** 层；
> - "将物理块号转换为物理设备地址（柱面、盘面、扇区号）" 属于 **物理文件系统** 层；
> - "磁盘调度、启动磁盘 I/O" 属于 **辅助分配模块/设备管理程序（设备管理）** 层。

**【易错】** 用户接口层收到的参数是**文件名**或**文件描述符 fd**，不是块号；块号是文件系统内部的概念。另外 open 时调用的"按名检索"属于**文件目录系统**层。

## 4.8 外存空闲空间管理

**问题**：磁盘上有一堆空闲块，怎么记账、怎么快速"找空位"？四种方法，从简单到精巧，考试热度递增：**空闲表法 → 空闲链表法 → 位示图法 → 成组链接法**。

### 4.8.1 空闲表法

一张表：每行 = 一块连续空闲区，记录（**起始块号，连续块数**）。

| 空闲区 | 首块号 | 块数 |
| --- | --- | --- |
| ① | 8 | 2 |
| ② | 13 | 3 |
| …… | …… | …… |

- 分配：找能满足长度的空闲区——**首次适应 / 最佳适应**（与内存管理的"首次/最佳"同一套思想，只是对象是磁盘块）；
- 回收：**合并相邻的空闲区**（回收区与前一区相邻则合并、与后一区相邻则合并）；
- 优点：适合**连续分配**方式（连续文件需要整块连续空闲区）；
- 缺点：表项数随空闲区数增长，为减少 I/O，可以用**链表**把空闲表串起来。

### 4.8.2 空闲链表法

- **空闲盘块链**：把每块空闲块的头部挂一个指针，串成链（适合显式链接/索引分配，按块分配）；缺点：每块都存指针；快慢看链长。
- **空闲盘区链**：把"连续空闲区"作为链表节点（记录首块号+长度），分配快；回收合并麻烦。

#### 深化学习：空闲表与空闲链的一图对照

![4-25 空闲表法与空闲链表法](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-24_free_table_chain.png)

*图4-25 空闲表法记"起始块号+长度"（配合连续分配，回收要合并相邻区）；空闲链表法把空闲块/区串成链（摘链即分配）。*

**图后解读要点**：

- **与离散分配的搭配关系（考点）**：空闲表法/空闲盘区链 → 天然服务**连续分配**；空闲盘块链/位示图/成组链接 → 服务**离散分配**（链接、索引、请求分页）；
- **盘块链 vs 盘区链**：盘块链"一块一节点"粒度细但链长；盘区链"一区一节点"一次给一大片，但回收时要做**相邻合并**（和动态分区回收一个套路）；
- 【易错】"空闲表法可用于离散分配" → **错**（它记的是"连续区段"，离散分配用位图/成组链接）。

### 4.8.3 位示图法（必考计算）

**【比喻】** 图书馆的"空位登记黑板"：一块黑板，每个格子对应一张书位，**划勾=有人（占用）、画圈=空位**。找空位看黑板，不用一间间房去数。

**原理**：用一个二进制位表示一个盘块：**1 = 该盘块已分配（占用），0 = 空闲**（**约定说明：各教材 0/1 含义可能相反，题目必有说明，以题意为准**）。位示图用一个矩阵（或一维数组）表示，每"字"有 32 位（字长 32）。

![位示图与计算例题](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-12_free_bitmap.png)

*图4-13 位示图法：矩阵行=字号、列=位号；互算公式 b=字号×32+位号；四个演算例题（b=25、65、100 与反向 (字号1,位号30)→b=62）*

**核心公式（字长 = 32，字号与位号都从 0 开始编号）**：

> **盘块号 b = 字号 × 32 + 位号**
> **字号 = b ÷ 32（整除）**，**位号 = b mod 32**

**【必做例题】** 字长 32 位，求下列盘块号的位置：

| 盘块号 b | 演算 | 位置（字号, 位号） |
| --- | --- | --- |
| 25 | 25 ÷ 32 = 0，25 mod 32 = 25 | （0, 25）|
| 65 | 65 ÷ 32 = 2，65 mod 32 = 1 | （2, 1）|
| 100 | 100 ÷ 32 = 3，100 mod 32 = 4 | （3, 4）|
| 反向：（1, 30） | b = 1 × 32 + 30 | **盘块号 62** |

- **分配**：查找某字中 =0 的位 → 置 1 → 由（字号,位号）算出 b 分配出去；
- **回收**：先由 b 算出（字号,位号）→ 把该位置 0。

**【考点·延伸】** ① 若字长是 16（或 8），公式变为 b = 字号 × 16 + 位号；② 位示图**可以整个放入内存**（1M 个盘块只需 1M bit = 128KB），适合超大容量磁盘；③ 但位示图**查找"连续"空闲块不方便**（要按位扫描），所以大系统通常与成组链接法结合使用。

#### 专项训练：位示图互算四连

![4-26 位示图互算练习](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-25_bitmap_exercises.png)

*图4-26 位示图互算：b=25/65/100 正推 (字号,位号)，以及 (5,30) 反推盘块号——全部一步除法/乘法搞定。*

**互算心法（背两句）**：

- **正推**：字号 = b div 字长；位号 = b mod 字长；
- **反推**：b = 字号 × 字长 + 位号；
- 【自测】字长 16 位时，盘块号 130 在哪？→ 130 = 8×16 + 2 → **8 号字第 2 位**（这也是本章自测题第 3 题的答案）；
- 【易错】题目若说"行列从 1 开始编号"，公式整体平移为 b = (字号−1)×字长 + (位号−1)——**看清编号起点再动笔**。

### 4.8.4 成组链接法（必考计算 ★★★）

**问题**：位示图太大（或磁盘太大）时，还有没有既省内存又高效的办法？——**UNIX 的成组链接法**。

**【比喻】** 把登记空位的本子分成"每 100 个空位一小本"，**只把当前这本放在手边（内存）**；每小本的**最后一页**贴一张"下一本在哪"的便签。手边这本用完了，翻最后一页的便签，自动换上新的一本。

**核心结构（对照下图一步步读）**：

1. **内存中维护一个"空闲盘块号栈"S**：最多 100 个块号，`S.top` 为栈中块数（**栈顶先分配**）；
2. **栈中这 100 个块号 = 第 1 组**，其中**S[0]（栈底，组内最后一个被分配的块）就是"连接块"**：它的磁盘块内容里存着**第 2 组的 100 个块号**；
3. 第 2 组的"连接块"（组内最后一个被分配的块，如前例的 1100）内容里又存**第 3 组的 100 个块号**……如此把全盘空闲块串成一条"链"；
4. **最后一组**：其末块内容为 **0**，表示"没有下一组"，链到此结束。

![成组链接法](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-13_grouped_linking.png)

*图4-14 成组链接法：内存盘块号栈（S[0]=1000 为栈底连接块，S[99]=1099 为栈顶先分配）→ 盘块 1000 存第 2 组块号（1100~1199）→ 盘块 1100 存第 3 组块号（1200~1299）→……；下方给出分配/回收的两种特殊情形与例题演算*

**两种特殊情形（必考演算）**：

**① 分配：栈中只剩 1 块（top = 1）时**
1. 先把该"连接块"（如块 1000）**内容读入栈**（栈中装满下一组的 100 个块号，top=100）；
2. 再把**块 1000 本身分配**给申请者（它的内容已被读走，没有损失）。

**② 回收：栈已满（top = 100）时**
1. 把栈中现有 **100 个块号整体写入回收块 R 的内容区**（"存档"）；
2. 栈中**只留下 R 一个块号**（top=1）——R 成为**新一组的连接块**（其余 99 块号"藏"在 R 的磁盘内容里）。

**【必做例题】** 假设初始状态：栈满，`S[0]=1000, S[1]=1001, ……, S[99]=1099`（top=100），盘块 1000 中存着下一组块号 1100~1199。逐步执行：**分配 3 块 → 回收 2 块（回收块为 2000、2001）**。

**演算**：

| 步骤 | 动作 | 栈内容 | top |
| --- | --- | --- | --- |
| 初始 | — | S[0..99] = 1000,1001,…,1099 | 100 |
| 分配第 1 块 | 弹出栈顶 S[99]=1099 | 剩 1000,…,1098 | 99 |
| 分配第 2 块 | 弹出 S[98]=1098 | 剩 1000,…,1097 | 98 |
| 分配第 3 块 | 弹出 S[97]=1097 | 剩 1000,…,1096 | 97 |
| 回收块 2000 | 压栈：S[97]=2000 | 1000,…,1096, 2000 | 98 |
| 回收块 2001 | 压栈：S[98]=2001 | 1000,…,1096, 2000, 2001 | 99 |

**最终栈**：`S[0]=1000, ……, S[96]=1096, S[97]=2000, S[98]=2001`，**top=99**（注意：连接块 1000 依然在栈底，未触发"top=1"的特殊情形）。

**再问**：继续分配多少块后会触发特殊情形？答：**再分配 98 块**时 top 降到 1（只剩连接块 1000），此时需先把 1000 中的下一组块号读入栈，再把 1000 分配出去。

> 【考点】成组链接法分配/回收的本质是：**"栈满的块"与"栈底的块"两种块都要当成连接块处理**。考试往往问："回收时栈满（top=100），如何处理？"答案就是"把栈内 100 块号写入该回收块，栈中只留该块号（top=1）"。

### 4.8.5 四种空闲空间管理方法对比

| 方法 | 数据结构 | 适合的分配方式 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| 空闲表法 | （起始块号, 长度）表（可链化） | **连续分配** | 简单，直接找连续区 | 表项随碎片增多；合并难 |
| 空闲盘块链 | 空闲块内部指针 | 链/索引分配 | 简单 | 每块存指针，链长时分配慢 |
| 空闲盘区链 | 空闲区节点链 | 连续分配 | 一次分配一大片 | 回收合并复杂 |
| 位示图法 | 1 位/块 的矩阵 | 各种 | **小，可常驻内存**；分配回收都 O(1) | 找连续空闲块难 |
| **成组链接法** | 盘块号栈 + 跨块链 | 各种（按块分配） | **内存只放 100 块号，支持超大磁盘**；分配回收都 O(1) | 实现较复杂 |

## 4.9 磁盘的结构与管理

### 4.9.1 磁盘的物理组成

![磁盘物理结构](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-14_disk_structure.png)

*图4-15 磁盘物理结构：左——俯视图（磁道/扇区）；中——侧视图（盘面、磁头、主轴、磁头臂）与柱面示意；右——CHS 地址与读盘三步*

**四个基本概念**：

| 概念 | 定义 |
| --- | --- |
| **盘面** | 每个盘片的上下两个面；每个盘面有一个**磁头**（所有磁头装在同一个磁头臂上，同步移动）|
| **磁道** | 一个盘面上，半径相同的一圈同心圆；**数据沿磁道连续存放**（相邻磁道间留空隙防干扰）|
| **扇区** | 磁道上划分的最小可寻址单元（通常 512B）；是磁盘读写的**最小单位** |
| **柱面** | **所有盘面上半径相同的磁道**组成的"圆柱面"；磁头臂移动一次可定位到整个柱面 |

### 4.9.2 磁盘地址：为什么柱面号在前

**磁盘地址 =（柱面号 : 盘面号 : 扇区号）**，如 (5:2:7)——第 5 柱面第 2 盘面第 7 扇区。

> **【考点】为什么柱面号排在最前？** 因为**移动磁头（寻道）是最慢的机械动作**；而同一柱面的所有盘面在同一时刻**并行可达**（所有磁头同步移动）。所以先把最慢的"柱面"定下来（一次寻道），然后再在**同一柱面上**选择盘面与扇区，**免去了多次寻道**。

**容量公式**：

> **磁盘总容量 = 柱面数 × 盘面数 × 每道扇区数 × 扇区大小**
> 或 = 柱面数 × 盘面数 × 每磁道容量

### 4.9.3 磁盘读写时间：寻道 + 旋转延迟 + 传输（必考计算）

读盘一个扇区要经过三步（**这就是磁盘时间的三个组成部分**）：

1. **寻道（Seek）**：磁头臂移动到目标柱面/磁道——**用时最多**，称**寻道时间 Ts**；
2. **旋转延迟（Rotational latency）**：等目标扇区转到磁头正下方——**平均半圈**，称旋转延迟 Tr；
3. **传输（Transfer）**：磁头读写数据，称传输时间 Tt。

![磁盘读写时间构成与例题](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-16_disk_time.png)

*图4-16 磁盘读写时间：三条时间条（寻道 6ms + 旋转延迟 5ms + 传输 0.1ms）+ 转盘示意图（平均旋转延迟=半圈）+ 完整例题演算*

**三个时间公式（背熟）**：

| 时间 | 公式/结论 | 说明 |
| --- | --- | --- |
| 寻道时间 | Ts = 启动时间 + 跨越的磁道数 × 每道移动时间 | 与寻道距离相关，最慢 |
| **平均旋转延迟** | **Tr = 1 / (2 × 每秒转速)** = 转一圈用时的一半 | 扇区均匀分布，平均等到半圈 |
| 传输时间 | Tt = 所读字节数 ÷（每扇区字节 × 每道扇区数 × 每秒转速）≈ 转一圈 ÷ 每道扇区数 | 读一整道 = 转一圈 |

**【必做例题】** 磁盘转速 **6000 r/min**，平均寻道时间 **6 ms**，每磁道 **100 个扇区**，每扇区 **512 B**。求平均读写一个扇区（一块）的时间。

**解（逐步）**：

1. 转速转成 r/s：6000 ÷ 60 = **100 r/s**；
2. 转一圈用时：1 ÷ 100 = 0.01 s = **10 ms**；
3. 平均旋转延迟：10 ms ÷ 2 = **5 ms**（转半圈）；
4. 传输时间：10 ms ÷ 100 扇区 = **0.1 ms**（每转恰好读一整道 100 个扇区）；
5. 平均访问时间 = Ts + Tr + Tt = **6 + 5 + 0.1 = 11.1 ms**。

> **【记忆口诀】** **寻道找圈、转盘等扇、读写传输**——三段时间按顺序串成一次磁盘访问；平均旋转延迟永远是"半圈"，跟转速只换算一圈时间即可。

**【考点】** 求"平均"时的默认假设：寻道取平均距离、旋转延迟取半圈，除非题目明确给出"寻道时间为 x 或扇区在磁头正下方（旋转延迟为 0）"。

### 4.9.4 磁盘的格式化与坏块管理

**① 低级格式化（物理格式化）**：在磁盘上**划出扇区**（写入扇区头、数据区、ECC 校验码）。

**② 高级格式化（逻辑格式化）**：建立文件系统结构——**初始化的关键三件事**：

1. 建立**根目录**（和空的目录系统）；
2. 建立**空闲空间管理结构**（如空闲表、位示图、成组链接法的初始链）；
3. 建立**文件表 / inode 表**等元数据区。

**③ 坏块（Bad blocks）**：物理损坏的扇区，两种处理：

- **扇区周转（搬迁）**：文件系统把坏扇区的数据搬到备用空闲扇区，坏扇区打上标记不再使用；
- **磁盘控制器级重映射**：硬件层面把坏扇区映射到备用区，操作系统**完全无感**（最简单）。

**【考点】** 低格式划扇区、高格式建文件系统结构（根目录+空闲空间结构+元数据区）——选择题常以"格式化做了哪些事"直接设问。

## 4.10 磁盘调度算法（重点计算题 ★★★★★）

### 4.10.1 目标：减少寻道时间

磁盘物理上最慢的是**磁头移动（寻道）**，因此调度的核心目标 = **让磁头移动的总距离最短**，从而减少平均寻道时间。磁盘调度在**设备管理**层（4.7 节第⑥层）完成。

**六个算法**按"从傻到聪明"排序介绍，先记一句话本质：

| 算法 | 一句话本质 |
| --- | --- |
| FCFS | 谁先来先服务谁（公平但颠簸） |
| SSTF | 每次都去**离当前磁头最近**的请求（贪心，可能饿死远的） |
| SCAN | **电梯算法**：沿当前方向扫到**磁盘最边缘 (0/199)** 才折返 |
| LOOK | 像 SCAN，但扫到**当前方向最远的请求**就折返（不到边缘） |
| C-SCAN | **单向**服务：扫到 199 后**快速跳回 0**，再向大号方向扫 |
| C-LOOK | 像 C-SCAN，但只扫到**两端最远的请求**就跳回另一端最远请求 |

**三种"反直觉"细节（考点密集）**：

1. **SSTF 是贪心、可能饥饿**（远处的请求永远轮不到），**不能保证避免饥饿**；
2. **SCAN 是双向扫描**（到了边缘才回头），**C-SCAN 是单向扫描**（扫到边缘就跳回起点，负载更均匀——两端请求等待时间更均衡）；
3. **LOOK/C-LOOK 不到边界**：只扫到"最远请求所在磁道"就转向/跳回，比 SCAN/C-SCAN 更省总距离。

### 4.10.2 【必做例题】六算法逐段演算与轨迹图（数据固定，已逐段验算）

**题目**：磁盘磁道号 **0~199**，磁头初始在 **53 号**磁道，**沿磁道号增大方向移动**。请求队列（按到达顺序）：**98, 183, 37, 122, 14, 124, 65, 67**。求各算法的服务顺序与总寻道距离。

![磁盘调度算法轨迹对比](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-15_disk_scheduling.png)

*图4-17 六种磁盘调度算法轨迹对比（横轴=磁道号 0~199，纵轴=服务顺序）：FCFS=640、SSTF=236、SCAN=331、LOOK=299、C-SCAN=382、C-LOOK=322；每段标注移动距离，灰色虚线为 C-SCAN/C-LOOK 的快速回程*

**① FCFS（先来先服务）**：完全按到达顺序。

| 段 | 53→98 | 98→183 | 183→37 | 37→122 | 122→14 | 14→124 | 124→65 | 65→67 | 合计 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 距离 | 45 | 85 | 146 | 85 | 108 | 110 | 59 | 2 | **640** |

服务顺序 = 队列原序：53, 98, 183, 37, 122, 14, 124, 65, 67。
特点：公平，但 183→37 这样的大跨度反复折磨磁头，**总距离最长（640）**。

**② SSTF（最短寻道时间优先）**：每次选"离当前位置最近的请求"。

| 当前 | 选择 | 距离 | 说明 |
| --- | --- | --- | --- |
| 53 | 65 | 12 | 离 53 最近的是 65（12）与 67（14）之比，98 有 45 |
| 65 | 67 | 2 | |
| 67 | 37 | 30 | 67 附近只剩 37（30），98 要 31 |
| 37 | 14 | 23 | |
| 14 | 98 | 84 | 远处的两个已到齐 |
| 98 | 122 | 24 | |
| 122 | 124 | 2 | |
| 124 | 183 | 59 | |

**总距离 = 12+2+30+23+84+24+2+59 = 236**。服务顺序：53, 65, 67, 37, 14, 98, 122, 124, 183。

> 【易错】SSTF 是**贪心最近**，不是"全局最优"；且理论上**会饿死**远处的等待请求（极端风暴场景）。本题它恰好是最优的（236 < 其余）。

**③ SCAN（电梯算法）**：从 53 开始**往磁道号增大方向扫**，途中的请求按序服务，**扫到最边缘 199 才折返**，折返后按减小方向继续服务。

- 去程：53 → 65(12) → 67(2) → 98(31) → 122(24) → 124(2) → 183(59) → **199**(16)，去程小计 **146**；
- 折返（从 199 往小）：199 → 37(162) → 14(23)，折返小计 **185**；
- **总计 = 146 + 162 + 23 = 331**。

**④ LOOK（到最远请求即折返）**：和 SCAN 一样先往大方向扫，但**最远请求是 183，不到 199** 就折返。

- 去程：53 → 65(12) → 67(2) → 98(31) → 122(24) → 124(2) → 183(59)，小计 **130**；
- 折返：183 → 37(146) → 14(23)，小计 **169**；
- **总计 = 130 + 146 + 23 = 299**。

**⑤ C-SCAN（单项扫描）**：去程同 SCAN 到 199，然后**从 199 跳回 0**，再往大方向扫完剩余请求：

- 去程：53 → 65 → 67 → 98 → 122 → 124 → 183 → 199，小计 **146**；
- **快速回程：199 → 0，距离 199**；
- 第二程：0 → 14(14) → 37(23)，小计 **37**；
- **总计 = 146 + 199 + 37 = 382**（**假设：快速回程距离计入总寻道距离**——多数 408 习题按计入计算，若题目说"回程不算寻道"则只算 183）。

**⑥ C-LOOK**：不到边界 199，到最远请求 **183** 就跳回最远小号请求 **14**：

- 去程：53 → 65 → 67 → 98 → 122 → 124 → 183，小计 **130**；
- 快速回程：183 → 14，距离 **169**；
- 第二程：14 → 37(23)；
- **总计 = 130 + 169 + 23 = 322**。

#### 深化学习：SCAN 与 LOOK 到底差在哪

![4-27 SCAN与LOOK对比](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-26_scan_look_diff.png)

*图4-27 同一数据下 SCAN（扫到边缘 199 才折返，总寻道 331）与 LOOK（到最远请求 183 即折返，总寻道 299）的轨迹对照。*

**图后解读要点**：

- **差的 16 道 = 183→199→折返这段"空跑"**：SCAN 机械地走到磁盘边缘，LOOK"见好就收"——代价与回报的权衡；
- **为什么说 SCAN 更"公平"**：若磁头长期停留在中部，边缘新来的请求要等很久；SCAN 保证"这一个方向总要扫到底"，边缘请求的等待有上界；LOOK 对边缘请求的等待时间理论上无上界；
- **C 系同理**：C-SCAN（382）之于 C-LOOK（322）也差了同样的"边缘空跑"——**算总寻道时，SCAN/C-SCAN 记得到边缘（0 或 199），LOOK/C-LOOK 只到最远请求**；
- 【答题模板】先画 0~199 数轴 → 标起点和请求点 → 按算法规则逐段走并标注每段距离 → 分段相加。

### 4.10.3 六算法对比表（必背）

| 算法 | 总寻道（本题） | 是否公平 | 饥饿 | 负载均匀性 | 特点 |
| --- | --- | --- | --- | --- | --- |
| FCFS | 640 | 最公平 | 无 | 差（颠簸） | 简单，最坏成绩 |
| SSTF | 236 | 不公平 | **可能** | 差（两端请求等待长） | 贪心，平均短但存在饥饿 |
| SCAN | 331 | 较公平 | 无 | 较好（两端都服务） | 折返扫到边界 |
| LOOK | 299 | 较公平 | 无 | 较好 | 折返于最远请求 |
| C-SCAN | 382 | 单向公平 | 无 | **最好（各磁道等待均匀）** | 快速回程，单向服务 |
| C-LOOK | 322 | 单向公平 | 无 | 最好 | 跳回最远小号请求 |

**【考点·计算套路】** ① 每段距离 = |相邻两个磁道号之差|；② 服务起始**默认从磁头当前方向**出发（方向题给，如本题"沿增大方向"）；③ SCAN/C-SCAN 的折返点写到**边界或最远请求**，别写错；④ 只去程的到达点也算"一次服务"。

> 【记忆口诀】**先来排队、最近贪恋、电梯到头、LOOK 到家、单向跳回、C-LOOK 抄近**：SCAN 与 LOOK 的区别只在"要不要扫到边界"，C-SCAN 与 C-LOOK 的区别同理。

## 4.11 磁盘阵列 RAID（了解级）

**RAID（Redundant Array of Independent Disks，独立磁盘冗余阵列）**：把多块磁盘组织起来，**并行读写提高性能 + 冗余提高可靠性**。

![RAID 0/1/5](/Users/levi/IdeaProjects/操作系统/第4章_文件管理/figures/ch4-17_raid.png)

*图4-18 RAID 0/1/5：左——条带化（数据分条交错存放）；中——镜像（每份数据写两处）；右——分布式奇偶校验（校验块 P 轮流分布在所有盘上）*

| 项目 | RAID 0 | RAID 1 | RAID 5 |
| --- | --- | --- | --- |
| 思路 | 条带化（无冗余） | 镜像 | 条带 + 分布式奇偶校验 |
| 容量利用率 | **100%**（N 盘=总容量） | **50%**（一半存副本） | **(N−1)/N**（一块盘的容量做校验） |
| 读性能 | 快（N 盘并行） | **更快**（可同时读多副本） | 快（近 RAID 0） |
| 写性能 | 快 | 较慢（每块写两处） | 较慢（要算校验值） |
| 容错 | **无**（坏 1 块全丢） | **强**（坏 1 块仍可用） | **中**（坏 1 块可由校验恢复） |

**考点提醒**：RAID 在 408 操作系统部分属**了解级别**（低频），但**计组课程会详细考**（如 RAID 5 的校验计算"坏盘数据的恢复"）。操作系统的要求：记住上述对比表即可。

| 磁盘时间 | 平均访问时间 = 寻道 + 1/(2×转速) + 传输；例：6+5+0.1=11.1ms |
| 调度 | FCFS 640 / SSTF 236 / SCAN 331 / LOOK 299 / C-SCAN 382 / C-LOOK 322 |
| RAID | 0 无冗余 100%、1 镜像 50%、5 分布式校验 (N−1)/N |

## ② 计算题套路清单

1. **混合索引访盘次数**：数"从 inode 出发到数据块，共经过多少个索引块+1"；先判断逻辑块号落在哪一级；
2. **位示图互算**：b = 字号×字长+位号；整除与取模，注意**从 0 编号**、字长是否 32；
3. **成组链接**：分配看栈顶（top=1 特殊）；回收看栈满（top=100 特殊）；画出（栈内容, top）二元组即可保分；
4. **磁盘时间**：转速→圈时→半圈延迟；传输=圈时/每道扇区数；三段时间相加；
5. **磁盘调度**：列（当前, 选择, 距离）表逐段相加；SCAN/LOOK 分清"到边/到最远请求"，C 系列分清"跳回 0/跳回最远请求"。

## ④ 易错点清单（≥8 条，考前一天看这条就够了）

1. **FAT 常驻内存**：显式链接读任意块 **1 次访盘**（先查内存 FAT 再读数据），隐式链接读第 i 块要 **i 次**；
2. **树形目录不利于共享**：支持共享的是"无环图目录 + 链接"（树形只能靠共享路径访问）；
3. **位示图编号从 0 开始**：b = 字号 × 字长 + 位号；0/1 约定看题意（1=占用 0=空闲是主流约定）；
4. **硬链接不能跨文件系统、不能给目录建硬链接**；软链接都可以，但目标删除后会**悬空**；
5. **连续分配的"随机访问快"建立在"读第 i 块 1 次访盘"上**，它的主要问题在**扩展与外部碎片**，与"访问速度"无关；
6. **SCAN 扫到【磁盘边缘】才折返，LOOK 扫到【最远请求】就折返**（差 16 与差 2 的锅：本题 199 vs 183）；
7. **C-SCAN/C-LOOK 的回程距离**：多数 408 习题**计入**总寻道时间（本题 382/322 按计入计算），题目如明确"回程不计寻道"则另行处理；
8. **平均旋转延迟 = 半圈**（Tr = 1/(2×转速)），不是一圈；传输是"转一圈的时间 ÷ 每道扇区数"；
9. **打开 ≠ 读数据，关闭 ≠ 删除**：打开只把目录项调入内存；close 只是计数 −1；
10. **inode 中不存文件名**：文件名只属于目录项，为了硬链接可以共享同一 inode；
11. **磁盘调度减少的是寻道时间**，旋转延迟由硬件固定、调度无法改变；
12. **格式化**：低格式=划扇区；高格式=建**根目录+空闲空间结构+元数据表**。

## ⑤ 真题风格例题（≥7 道，含完整解析）

**例 1（混合索引·基础）** 某文件系统块大小 4KB，块地址 4B，inode 含 8 个直接地址、1 个一级间接、1 个二级间接。设 inode 已调入内存，各索引块未在内存：
① 该文件最大约多大？② 读文件第 0 块、第 100 块、第 3000 块（逻辑块号从 0 开始）分别需要几次访盘？

**解**：
① 每索引块项数 = 4KB/4B = 1024；容量 = 8×4KB + 1024×4KB + 1024×1024×4KB = 32KB + 4MB + 4GB ≈ 4.004GB；
② 直接区 0~7（8 块）：第 0 块 → **1 次**；一级间接区 8~1031（1024 块）：第 100 块 → **2 次**；二级间接区 1032~1049639?（精确：1032~1049607）：第 3000 块 → 3000 > 1031，落在二级间接区 → **3 次**（一级索引块 + 二级索引块 + 数据块）。

**例 2（位示图·变体）** 磁盘共 64MB，块大小 1KB，采用字长 16 位的位示图（1=占用，0=空闲，字号/位号从 0 开始）：
① 位示图占多少位？② 盘块号 2000 对应的（字号,位号）？③（字号 5，位号 3）对应哪个盘块？

**解**：① 盘块数 = 64MB/1KB = 65536 块 → 位示图 65536 位 = 8KB（或 4096 字 × 16 位）；
② 字号 = 2000 ÷ 16 = 125，位号 = 2000 mod 16 = 0 →（125, 0）；
③ b = 5×16 + 3 = **83**。

**例 3（成组链接·演算）** 某系统用成组链接法（每组最多 100 块）。当前栈满，栈中块号为 2000~2099（S[0]=2000 为栈底连接块，其内容为下一组块号 2100~2199）。
① 连续分配 5 块后，栈与 top 如何？② 此时回收块 2501、2502，栈与 top 如何？③ 若继续分配到只剩 1 块，会发生什么？

**解**：① 分配弹栈顶：2099、2098、2097、2096、2095 依次弹出，栈剩 2000~2094，**top = 95**；
② 回收压栈：S[95]=2501、S[96]=2502，**top = 97**，栈 = 2000~2094, 2501, 2502；
③ 再分配 94 块后 top=1（只剩连接块 2000）：此时**先把盘块 2000 的内容（2100~2199）读入栈（top=100），再把 2000 分配出去**。

**例 4（磁盘调度·计算）** 磁道 0~199，磁头在 50 号，正往磁道号增大方向移动。请求：82, 170, 43, 140, 24, 16, 190。求：① SSTF 总寻道；② SCAN 与 LOOK 分别的服务顺序与总寻道。

**解**：① SSTF：50→43(7)→24(19)→16(8)→82(66)→140(58)→170(30)→190(20)，**总计 208**；
② SCAN：去程 50→82(32)→140(58)→170(30)→190(20)→边界199(9)，折返 199→43(156)→24(19)→16(8)；总 = 32+58+30+20+9+156+19+8 = **332**；服务顺序 50,82,140,170,190,199,43,24,16；
③ LOOK：去程到最远 190 即回：50→82(32)→140(58)→170(30)→190(20)，回程 190→43(147)→24(19)→16(8)；总 = 32+58+30+20+147+19+8 = **314**。

**例 5（磁盘时间·计算）** 磁盘转速 7200 r/min，平均寻道 8ms，每磁道 200 扇区，每扇区 512B。求读一个扇区的平均时间。

**解**：转速 120 r/s → 一圈 8.33ms → 平均旋转延迟 ≈ 4.17ms；传输 = 8.33/200 ≈ 0.04ms；**总 ≈ 8 + 4.17 + 0.04 = 12.21ms**。
（提示：若题目要精确值：10³/120 = 8.33ms；4.167ms；0.0417ms。）

**例 6（逻辑结构·查找）** 某索引顺序文件有 400 条记录，分 20 组、每组 20 条。求平均比较次数，并与纯顺序查找对比。

**解**：查索引表平均 20/2 = 10 次，组内平均 20/2 = 10 次，**共约 20 次**；纯顺序查找 ≈ 400/2 = **200 次**；效率提高 10 倍。若组数=组内条数=√400=20 时最优（a/2+b/2 = 10+10 = 20）。

**例 7（目录检索·I/O）** 磁盘块 1KB，目录项 64B；改用 inode 方案后目录项 16B（文件名+inode 号+类型等精简字段）。查找某文件需要读取的目录块数最多分别是多少（目录共 640 项）？

**解**：① 每块目录项数：1KB/64B = 16 项；640 项 ÷ 16 = **40 块**；② 瘦身后：1KB/16B = 64 项；640 ÷ 64 = **10 块**；检索 I/O 从 40 块降到 10 块（**降为 1/4**），目录检索明显加速——这就是索引结点（inode）的意义。

**例 8（层次结构·判断）** 下列功能分别属于文件系统哪一层：① 把逻辑块号 3 转换为物理块号 100；② 检验用户是否有读权限；③ 查找目录项；④ 启动磁盘 I/O 并调度磁头。

**解**：① **逻辑文件系统与文件信息缓冲区**层；② **存取控制模块**；③ **文件目录系统**；④ **辅助分配模块/设备管理程序**（设备管理）。

**例 9（硬软链接·综合）** 文件 F 有 nlink=3；删除一个目录项后 nlink=？F 是否释放？在 F 上建软链接 s 后，F 的 nlink 与 s 的 nlink 各如何？rm F 后访问 s 会？

**解**：删 1 个目录项 → nlink=2，不释放；软链接 s 是独立文件：F 的 nlink **不变（仍 2）**，s 的 nlink=1；rm F → nlink=1（还有 1 个目录项）——等等，注意：F 被 rm 后 nlink 2→1，**F 未释放**！访问 s 仍成功？（s 内容是路径 F，F 还在）——是的！这里和 4.5.2"悬空"的区别在于：**只要计数 ≥1，硬链接的路径仍然有效**。本题要点：软链接是否悬空取决于"**路径指向的目录项**是否存在"，即 rm 的是不是最后一个目录项。若再删另一个目录项，nlink=0，F 释放，s 悬空。

**例 10（FAT 专项）** 磁盘 100GB、块大小 4KB、FAT 每项 4B。问 FAT 需占多少内存？改用隐式链接读第 1000 块要几次访盘？改用 FAT 呢？
**解**：总块数 = 100GB/4KB = 25M 块 → FAT 占 25M×4B = **100MB 内存**（块越小表越大）。隐式链接读第 1000 块：顺链爬要逐块读盘 **1000 次**；FAT：内存查表 999 次 + 读盘 **1 次**——这就是"显式"二字的全部意义。

**例 11（成组链接·特殊情形）** 空闲栈现有 99 个空闲块号（top=99）。问：① 再分配 2 块的过程？② 回收 2 块的过程？③ 若继续分配到只剩 1 块号（该块是"连接块"）时再分配，怎么办？
**解**：① 弹出栈顶 2 块号分配，top=97（普通情形）；② 回收块号压栈，top=101？不行——栈满 100 会溢出！若回收前 top=99，回收 1 块后 top=100 **已满**，再回收第 2 块时：**把栈内 100 个块号写入这块回收块，栈中只留该块号（top=1）**——它成为新的"连接块"；③ 栈中只剩的 1 块是连接块：先把**该块中记录的下一组块号读入栈**（top=100），再把这一块分配出去。

**例 12（磁盘时间·完整版）** 磁盘转速 7200 r/min，每磁道 200 扇区，每扇区 512B，寻道时间 = 启动 4ms + 每跨越一条磁道 0.2ms，目标在相邻磁道（跨 1 道）。求平均读写一个扇区的时间。
**解**：旋转延迟 = 转半圈 = 60/7200/2 = **4.17ms**；传输 = (60/7200)/200 = **0.042ms**（转一圈读一整道，一个扇区占 1/200 圈）；寻道 = 4 + 0.2×1 = **4.2ms**；合计 ≈ **8.4ms**。（注意"平均"旋转延迟取半圈；若题目给的是"平均寻道时间"则直接用给定值，不再按跨越道数算。）

### 参考答案与提示

1. **B**（open 搬元数据不搬数据；返回 fd）。 2. **B**（索引表按关键字排序可二分）。 3. **B**（FAT 常驻内存，跳链 0 次访盘）。 4. **B**（树形不利于共享；无环图才支持）。 5. **A**（130 = 4×32 + 2）。 6. **B**（SCAN 到磁盘边缘）。 7. **B**（A 是低级格式化；C 在低格/检测阶段）。 8. **B**（逻辑块号→物理块号是物理文件系统的职责，随后由设备管理程序驱动 I/O）。
9. ① 1KB/4B = **256** 项；② 最大 = 8 + 256 + 256² = 65544 块 = **8KB + 256KB + 64MB ≈ 64MB 略多**；③ 直接 **1** 次、一级 **2** 次、二级 **3** 次。
10. 500KB ÷ 1KB = 500 号逻辑块；500 − 8 = 492 < 256 → **一级间接区 → 2 次访盘**。
11. ① 745 = 46×16 + 9 → **46 号字第 9 位**；② 30×16 + 15 = **495**。
12. 500GB/2KB = 256M 块 → 256M × 4B = **1GB 内存**。权衡：FAT 用内存换"任意块 1 次访盘"的随机访问能力；块越小表越肥——这正是它在大盘上受限的原因。
13. 每转 60/10000 = 6ms → 平均旋转延迟 = **3ms**；传输一个扇区 = 6/160 = **0.0375ms**；合计 8 + 3 + 0.0375 = **11.04ms**。
14. SSTF：80→90(10)→110(20)→130(20)→170(40)→40(130)→20(20) = **240**；LOOK：80→170(90) 再折返 170→20(150) = **240**（本组数据两者恰好相等）；SCAN：80→199(119) + 199→20(179) = **298**；C-LOOK：80→170(90) + 跳回 20(150) + 20→40(20) = **260**。
15. ① 弹出栈顶 3 个块号分配，top 由 98→95，普通情形；② 栈中仅剩的块是连接块：**先把该块中记录的下一组块号读入栈（top=100），再把这块分配出去**。
16. 连续 **1** 次（直接算出物理块）；隐式链接 **i+1** 次（逐块顺链）；FAT **1** 次（内存查表 + 读盘）；单级索引（inode 在内存）**2** 次（索引块 + 数据块）。
17. 目录项只留"文件名 + inode 号"后，一个磁盘块能装更多目录项 → 检索目录（按名比对）时读盘次数显著减少；其余元数据集中放 inode，便于共享（硬链接 = 多目录项指同一 inode）。
18. 同文件系统内给"同一份资料"建多个入口（如工具的多个 PATH 入口）→ 硬链接（省空间、计数管理）；跨文件系统/跨机器挂载引用、或希望"删源不连坐"的快捷方式语义 → 软链接（独立文件存路径，可悬空）。
19. 常见约定 **0=空闲、1=已分配**（也有教材相反）。公式 b=字号×字长+位号 不受影响，但"找空闲位"扫描的判断值相反——约定看错，整道题方向全反。
20. 寻道是机械运动、最慢；把柱面号放高位使相邻地址大概率同柱面 → 顺序访问时几乎不用移动磁头（同柱面多盘面还可并行读写），性能最优。
