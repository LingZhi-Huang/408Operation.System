## 5.1 I/O设备概述：先认识"送货的伙计"

### 5.1.1 什么是I/O设备

**I/O设备**（输入/输出设备）就是**与计算机主机进行数据交换的外部设备**，也叫外围设备。教材里的定义是：I/O设备由**机械部件**（真正干活的部分，如打印头、磁头）和**电子部件**（驱动的电路）组成，电子部件通常由设备控制器负责管理——这句话先存着，5.2节就讲控制器。

**【记忆口诀】** I/O设备 = 一堆"又慢又笨的打工机器"，主机为了不和它死磕，才生出了控制器、缓冲区、中断这一整套"保姆体系"。

### 5.1.2 设备分类的三个视角（高频考点）

描述一台设备，可以站三个角度看它：**按使用特性**、**按传输速率**、**按信息交换单位**。

![5-1 I/O设备分类](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-01_io_classification.png)

*图5-1 设备分类三种视角：使用特性（人机交互/存储/网络通信）；传输速率（低/中/高速）；信息交换单位（块设备/字符设备）。*

**视角一：按使用特性分类**

| 类别 | 典型设备 | 特点 | 常配合的控制方式 |
| --- | --- | --- | --- |
| **人机交互设备** | 键盘、鼠标、显示器、打印机 | 人与机器交换信息；速度**慢** | 中断驱动、程序直接控制 |
| **存储设备** | 磁盘、光盘、磁带、U盘 | 机器内部保存大量数据；速度**快**、**可寻址** | DMA（成块传送） |
| **网络通信设备** | 网卡、调制解调器、蓝牙 | 设备与设备间通信；中速 | DMA/中断，以帧为单位 |

**视角二：按传输速率分类**

| 类别 | 速率量级 | 典型设备 |
| --- | --- | --- |
| 低速设备 | 几个字节～几百字节/秒 | 键盘、鼠标、打印机、语音输入 |
| 中速设备 | 几千～几万字节/秒 | 激光打印机、网卡、终端 |
| 高速设备 | 几十万～几百万字节/秒（甚至更高） | 磁盘、光盘、SSD |

> 记法：速率的本质差异是**机械运动（键盘按键、打印头）vs 电子信号（磁盘磁头、网卡）**——机械的必然慢，电子的必然快。

**视角三：按信息交换单位分类（最重要，几乎必考）**

| 对比项 | **块设备** | **字符设备** |
| --- | --- | --- |
| 传输单位 | **一块**（若干字节组成的块，大小固定，如512B/1KB） | **一个字符 / 一个字节** |
| 典型设备 | 磁盘、光盘、磁带 | 键盘、鼠标、打印机、显示器、终端 |
| **可寻址性** | **可寻址**（按块号随机访问，像数组按下标访问） | **不可寻址**（只能按到达顺序"排队"读入） |
| 速度 | 较快 | 较慢 |
| 常采用的控制方式 | 常结合 **DMA**（成块传送、一次中断） | 常采用 **中断驱动**（一个字符一个字符送） |

**【考点】给设备判断类别——一句话决策树**：

```
题目给出一个设备？
├── 能按"块号"随机访问（磁盘/光盘）→ 块设备、可寻址、常配DMA
├── 只能逐个字符输入（键盘/鼠标/打印机）→ 字符设备、不可寻址、常配中断
└── 看用途：人机交互/存储/网络通信 → 第一视角分类
```

【真题风格例题】判断正误：磁盘是块设备，可寻址；键盘是字符设备，不可寻址。（✓）
打印机是块设备。（✗，打印机按字符传输，是字符设备）

**【易错】** 磁带：按信息交换单位算是**块设备**（成块读写），但它是**顺序访问**、不可随机寻址——"块设备可寻址"这句话要理解成"可以按块号定位"，磁带的块号定位需要移动磁头（顺序），所以常考判断题"磁带可随机访问"是**错**的。

#### 深化学习：块设备与字符设备的一图对照

![5-14 块设备与字符设备对比](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-14_block_char_devices.png)

*图5-14 块设备 vs 字符设备：块设备按块寻址可随机读（磁盘/SSD），字符设备按字节流顺序传输不可寻址（键盘/打印机）。*

**图后解读要点**：

- **"可寻址"的准确理解**（呼应上面磁带的易错）：块设备的"第 n 块"可以直接定位（磁盘把磁头移到对应位置）；字符设备连"第 n 个字符在哪"这个概念都没有，只能从头顺着读；
- **与 I/O 控制方式的搭配（选择题）**：字符设备速率低 → 中断驱动"按字中断"够用；块设备数据量大 → 必须配 DMA/通道"按块传输"；
- 【延伸】**网络设备**既非块也非字符，走独立的 socket 接口——408 判断题曾以"网络设备属于字符设备"挖坑。

## 5.2 I/O控制器（设备控制器）：CPU与设备之间的"翻译官"

### 5.2.1 为什么需要控制器

CPU是"讲汉语"的高速大老板，设备是"讲方言"的慢吞吞工人。如果让CPU直接操作设备，会出现三个问题：

1. **速度差距太大**：CPU几纳秒一个动作，设备几千微秒才动一下，CPU会等到崩溃；
2. **细节太多**：设备有各种机械/电气细节（磁头定位、打印头预热、电平信号），CPU不该管；
3. **适配差**：设备五花八门，没有统一的接口，操作系统没法写代码。

所以中间加一层**设备控制器（I/O控制器）**，它相当于"翻译官+工头"：CPU只对控制器说话（一句话：读/写/定位），控制器负责指挥设备干完活，再把结果汇报给CPU。

### 5.2.2 控制器的组成，重点记住"三类寄存器"

![5-2 设备控制器组成](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-02_device_controller.png)

*图5-2 设备控制器组成：CPU通过系统总线访问控制器，控制器内部有三种寄存器+设备控制逻辑，右边"与设备接口"连到设备（机械部件+电子部件）。*

控制器可以概括为**"三寄存器 + 一逻辑"**：

| 寄存器 | 干什么（谁读写） |
| --- | --- |
| **数据寄存器 DR（数据缓冲）** | 暂存CPU与设备之间交换的数据：CPU写DR=送数据给设备；CPU读DR=从设备取数据。起**缓冲**作用 |
| **状态寄存器 SR** | 存放设备当前状态：忙/就绪（空闲）、传输完成、有无错误（校验错、格式错）等状态位，CPU靠读它判断设备是否就绪 |
| **控制寄存器 CR（命令寄存器）** | 存放CPU下发的**命令字与参数**：读/写/定位、传送块号、传送长度等 |
| **设备控制逻辑** | 解释命令、控制设备完成操作、把设备状态翻译成状态寄存器中的位；负责与设备的接口（数据/状态/命令信号线） |

> 【记忆口诀】**"数（据）状（态）控（制）"三层数据**：数据寄存器放"货"，状态寄存器放"牌"（忙不忙），控制寄存器放"令"（干什么）。CPU与控制器之间的交互 = 写命令（CR）+ 查状态（SR）+ 搬数据（DR）。

### 5.2.3 端口编址的两种方式：内存映射I/O vs 独立编址（小对比，考点）

CPU要访问控制器里的寄存器，就要给寄存器分配"地址"，即**端口（端口地址）**。有两种分法：

| 对比项 | **内存映射I/O（统一编址）** | **独立编址** |
| --- | --- | --- |
| 思路 | I/O端口与内存单元编入**同一个**地址空间 | 端口地址空间与内存地址空间**相互独立** |
| 访问指令 | 用**普通内存指令**（如MOV）即可读写端口 | 需**专门I/O指令（IN / OUT）** |
| 优点 | 无需专门I/O指令，指令集简单，编程灵活；可对端口做各种内存运算 | **不占用内存地址空间**；专门指令更安全，不易误用 |
| 缺点 | **占用内存地址空间**，内存可寻址范围被"挤占" | 需专门指令，指令集复杂；CPU需要额外的端口地址线 |
| 典型例子 | ARM、MIPS、多数单片机 | x86 的 IN / OUT |

**【考点】判断编址方式特点**：看到"端口与内存统一编址"就选"可用内存指令访问"；看到"专门IN/OUT指令"就选"独立编址、不占内存空间"。

【真题风格例题】下列说法正确的是（ ）
A. 统一编址方式下，I/O端口占用内存地址空间
B. 独立编址方式下，可以用MOV指令访问端口
C. 内存映射I/O不需要专门的I/O指令，因此指令集一定更复杂
D. 独立编址方式占用内存地址空间

解析：**A**。B错，独立编址需IN/OUT；C错，统一编址反而使指令集更简单；D错，独立编址不占内存空间。

## 5.3 I/O控制方式（本章绝对重点）

有了控制器，CPU和设备之间的"对话流程"由谁来管？这就有四种控制方式，它们本质上是一道**演进史**：CPU越来越闲，数据搬运越来越自动化。

### 5.3.1 演进总览

![5-3 四种I/O控制方式对比](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-03_io_control_methods.png)

*图5-3 四种控制方式的"CPU泳道/设备泳道"时间轴：①轮询：CPU全程忙等；②中断：每字中断一次；③DMA：整块传完中断一次；④通道：一批数据一次中断。*

四种方式的核心差异，先看这张总对比表（要求背熟）：

| 对比项 | ①程序直接控制（轮询） | ②中断驱动 | ③DMA | ④通道 |
| --- | --- | --- | --- | --- |
| 数据传送单位 | **字 / 字节** | **字 / 字节** | **块** | **一批数据（多块）** |
| CPU干预时机 | 每个字都要CPU读状态、搬运、写回 | 每传完**一个字**中断一次，CPU处理这个字 | CPU只在**初始化**时设参数 + **一块传完**时处理中断 | CPU只在**初始化通道程序** + **一批完成**时处理中断 |
| CPU与设备并行度 | **无并行**（CPU死等） | 较高（但中断频繁，开销大） | 高（整块传送期间CPU完全不参与） | **最高**（CPU干预最少） |
| 硬件成本 | 最低 | 中（需中断控制器） | 较高（DMA控制器） | 最高（通道=一台I/O处理机） |
| 适用场景 | 早期系统、简单环境 | 低速字符设备（键盘、打印机） | 高速块设备（磁盘） | 大型机、多外设批处理（如磁带↔内存↔打印机） |

### 5.3.2 ① 程序直接控制方式（轮询，polling）

**做法**：CPU 循环执行：`读状态寄存器 → 判断"就绪？" → 没就绪就再读 → 就绪了由CPU亲自把数据从数据寄存器搬到内存（或反向）`。

```text
do {
    while (控制器状态寄存器.RBUSY == 1);   // 忙，继续轮询
    数据 = 控制器数据寄存器;                 // CPU读走一个字
    存入内存;                                // CPU亲自搬
} while (还有数据);
```

**特点**：CPU全程**忙等**（busy waiting），一无所有地占死CPU；每传一个字，CPU都要亲自读→搬→写。CPU与设备**完全串行**。

> 【记忆口诀】轮询 = "打电话一直占线重拨"：CPU像盯梢一样一遍遍问"好了没？好了没？"——设备还没好，CPU已经累瘫。**CPU利用率极低**，只适合简单设备。

#### 深化学习：把轮询画成流程图，看清 CPU 在哪空转

![5-15 程序直接控制流程](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-15_polling_flow.png)

*图5-15 轮询的循环：读状态→忙？→是则原地再读。设备慢，CPU 全部时间耗在"问"上。*

**图后解读要点**：

- **算一笔账**：键盘打字员每秒敲 5 个字 = 每 200ms 一个字；CPU 若以 100ns 一次的频率查状态寄存器，一个字要**空转 200 万次**查询——利用率近乎 0%；
- **唯一优点**：无需硬件支持（不用中断控制器）、实现最简单——所以单片机/简单外设仍在用；
- 【考点】轮询方式下 CPU 与设备**串行**工作；判断"轮询方式可实现 CPU 与设备并行" → **错**。

### 5.3.3 ② 中断驱动方式（interrupt-driven）

**思想**：设备干活时，CPU**先撤**；设备干完一个字，**主动向CPU发中断请求**，CPU搁下手头工作，**执行中断处理程序**（把数据寄存器中的字搬走，判断下一字继续），然后恢复现场继续原任务。

**流程**：CPU发起I/O → 设备工作（CPU旁去做其他任务）→ 设备完成一个字 → **中断请求** → CPU保存现场→中断处理（搬运）→恢复现场 → 设备继续传下一个字……

**特点**：
- CPU与设备**可以并行**（设备传第二个字时，CPU处理第一个字），这是对轮询的巨大进步；
- 但**仍是按"字"传输，每传一个字就中断一次**。若传送一个文件有n个字，就要中断n次；而**每次中断都要保存/恢复现场**，开销大；
- 适合低速字符设备（键盘、打印机）。

**【易错】** 中断驱动中"搬运数据"的还是**CPU**（在中断处理程序里把字从数据寄存器搬进内存）——只是搬运时间变成了"碎片化"，CPU不被死等了。

#### 深化学习：中断驱动的五步全程

![5-16 中断驱动流程](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-16_interrupt_io_flow.png)

*图5-16 中断驱动五步：发命令→CPU撤→设备干活→一字准备好就中断→CPU搬走再发令→循环。*

**图后解读要点**：

- **对比轮询的本质区别**：CPU 的角色从"主动盯梢"变成"被动接单"——设备好一个字才叫 CPU 一次，两次中断之间 CPU 完全自由；
- **代价**：每次中断都有**保存/恢复现场**的固定开销；传 1KB 数据按字中断 = 1024 次现场切换——这就是"中断次数太多"的痛点，直接催生 DMA；
- 【考点】"中断驱动方式下数据的传送方向是 设备→控制器→CPU（寄存器）→内存"——**数据要过 CPU 的手**，这是它与 DMA 的根本区别。

### 5.3.4 ③ DMA方式（Direct Memory Access，直接内存存取）

中断驱动每字中断一次太烦人，于是引入**DMA控制器**：让"设备↔内存"的数据流**完全不经过CPU**，由DMA控制器直接搬运一整块。

![5-4 DMA方式流程与寄存器](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-04_dma_flow.png)

*图5-4 DMA流程：①CPU初始化CR/MAR/DC（虚线控制信号）；②设备按字传给DR；③整块数据经DMA直接进内存（不经过CPU寄存器）；④传满一块（DC=0）→才向CPU发一次中断；⑤CPU善后。*

**DMA控制器里的四个寄存器（必背）**：

| 寄存器 | 作用 |
| --- | --- |
| **CR：命令/状态寄存器** | 存放命令（读/写）和状态 |
| **MAR：内存地址寄存器** | 存放所读写内存的起始地址（每传一个字自动+1） |
| **DC：数据计数器** | 存放剩余要传的字数（每传一个字自动-1；**DC=0 → 一块传完 → 中断CPU**） |
| **DR：数据寄存器（缓冲）** | 暂存设备与内存之间正在传的那个字（DMA控制器内部的数据缓冲） |

**流程（读磁盘为例）**：
1. **CPU初始化**：把"读命令"写入CR，把内存起始地址写入MAR，把块长（字数）写入DC；
2. DMA控制器开始工作：**设备 → DR → 内存**，每传一个字，MAR自动加1、DC自动减1；
3. 数据传输**不经过CPU**，CPU可以继续执行其他程序（整块传送期间CPU与设备高度并行）；
4. **传送完一整块（DC=0）**，DMA控制器向CPU发出**一次中断请求**；
5. CPU响应中断，做善后（例如确认数据已就绪、唤醒等待该数据的进程）。

**特点**：
- 数据传输单位是**块**；
- 中断频率从"每字一次"降到"**每块一次**"；
- **数据通路绕开CPU**（设备↔内存），CPU真正"解放"。

> **【易错·必背】** DMA传送数据**不需要CPU执行程序搬运**（数据直接设备→内存）；但DMA的**初始化（设置CR/MAR/DC）**和**结束处理（响应中断、善后）**仍然需要CPU参与。所以"DMA方式下CPU完全不参与I/O"是错的——CPU参与头尾，不参与中间搬运。

> **【易错】** DMA传送期间，DMA控制器与CPU可能**同时要求访问内存总线**（争用总线），这时需要**周期挪用**（CPU让出一个存取周期给DMA），这也是内存带宽的一大开销来源。

### 5.3.5 ④ 通道方式（I/O处理机）

DMA传一整块已经很省事了，但**一块一块的初始化还是要CPU干**（每块都要设置CR/MAR/DC）。通道方式更进一步：把"初始化、控制、读完一块再读下一块"这件事也外包，交给一**台"弱弱的CPU"——通道（I/O处理机）**。

**通道**是一种特殊处理器：它能取出/执行**通道程序**。CPU只需：
1. 把通道程序的首地址交给通道；
2. 通道自己取指、执行通道程序，控制设备、控制器完成**一批数据（可能包含多块）**的传送；
3. **一批数据全部传完**，通道才向CPU发**一次中断**。

**特点**：
- 数据传输单位是一**批数据**（多块）；
- CPU干预**最少**：初始化 + 每批一次中断；
- 硬件成本**最高**（通道本身是一台处理器）；
- 适用于大型机系统（如：从磁带读一批数据到内存，再输出到打印机，全程通道负责）。

**【易错】** 通道中断 ≠ 设备中断：设备完成一个单词/一块要不要中断？不一定——**通道完成一批才中断CPU**；设备层面的"完成"由通道自己收集，不惊动CPU。

#### 深化学习：通道为什么是"弱化 CPU"而不是"加强 DMA"

![5-17 通道方式流程](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-17_channel_flow.png)

*图5-17 通道方式：CPU 把"通道程序"交给通道执行，数据设备→内存直传；全部传完才中断一次。层级链：CPU→通道→控制器→设备。*

**图后解读要点**：

- **DMA 与通道的分界**：DMA 控制器**只会**"按预置的参数搬一块数据"（MAR/DC 写死后机械执行）；通道**能执行程序**（通道程序存放在内存，含多条通道指令：读、写、转移…），能协调**多台不同设备**完成"读磁带→加工→写打印机"这种复杂流程；
- **CPU 的干预点对比**（选择题常排序）：轮询（全程盯）> 中断（每字一次）> DMA（每块一次）> 通道（每批一次）；
- 【易错】"通道完全独立于 CPU" → **错**：通道的启动指令、通道程序都由 CPU 准备；出错时仍要向 CPU 报告。"通道有独立指令系统" → 对（通道指令，不是 CPU 指令集）。

### 5.3.6 中断驱动 vs DMA：一张图说透（重要）

![5-5 中断驱动 vs DMA](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-05_interrupt_vs_dma.png)

*图5-5 左：中断驱动按"字"中断，CPU每一字都要被叫醒一次；右：DMA按"块"中断，一整块传完才叫醒CPU一次。表格给出五维对比。*

**【记忆口诀】** 中断驱动 = "每卸一个包裹都要老板签字"；DMA = "一整车卸完老板才签字"；通道 = "老板直接把仓库钥匙交给车队队长（通道程序），一单生意做完才汇报"。

**【真题风格例题】** 单选题：与中断驱动方式相比，DMA方式的主要优点是（ ）
A. 不需要CPU干预
B. 传送单位更大，中断次数更少
C. 不需要中断
D. 不需要初始化

解析：**B**。DMA传送单位是块，每块才中断一次，中断频率大大降低。A错（初始化与善后仍需CPU）；C错（传完一块仍然要中断一次）；D错（初始化是必须的）。

【易错判断】"DMA方式下，CPU在任何时刻都不参与数据传送"（错——不参与数据搬运，但参与初始化与善后；若指搬运，则对）。

## 5.4 I/O软件层次结构（本章绝对重点）

刚才讲的轮询/中断/DMA/通道是**硬件怎么干活**；现在讲**软件怎么组织**：操作系统把I/O软件分成**四层**，每一层只信任下层、只服务上层，越往下越接近硬件。

![5-6 I/O软件四层结构](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-06_io_layers.png)

*图5-6 I/O软件四层结构（含硬件）：用户层I/O软件→设备独立性软件→设备驱动程序→中断处理程序→硬件。右侧标注每层职责与向上接口；底部以“读磁盘一个数据块”为例，请求下行、完成信号上行。*

### 5.4.1 各层职责与向上接口

| 层次 | 职责（干什么） | 向上接口 | 一句话印象 |
| --- | --- | --- | --- |
| **用户层I/O软件** | 用户接口、**库函数**（printf/scanf）、**SPOOLing的用户态部分** | 系统调用 read/write/print | 用户只喊“我要读一块”，不懂设备 |
| **设备独立性软件** | **设备命名与保护**、**逻辑设备名→物理设备名映射**、**缓冲管理**、**设备分配与回收**、**差错处理（通用部分）** | 设备无关（不区分具体设备）的系统调用 | “行政前台”：不管你用哪家设备，服务流程一样 |
| **设备驱动程序** | 唯一“懂硬件控制器”的软件层：把**抽象命令翻译成对寄存器的读写**（写CR发命令、写DR送数据、读SR看状态）、**检查设备状态**、启动设备 | 面向设备的统一命令接口 | “车间主任”：只有他知道设备的脾气 |
| **中断处理程序** | **保存现场**→**识别中断来源**→处理I/O完成事件→**唤醒等待进程**→恢复现场 | 中断向量（硬件中断的入口） | “售后服务部”：设备干完活的善后者 |

> 【记忆口诀】**“用户—管理—驱动—中断”**：**用**户喊（库函数）、**管**理批（独立性软件做分配/缓冲/映射）、**驱**动干（写寄存器）、**中断**收尾（保存现场、唤醒进程）。越往下越“硬”，只有驱动接触控制器寄存器。

### 5.4.2 一个请求的完整旅程：“读文件一块”（务必看熟图5-6底部）

1. 用户进程调用 `read(fd, buf, len)` —— **用户层**；
2. 系统调用进入**设备独立性软件**：查权限（设备保护）→ LUT把逻辑设备名转成物理设备名 → 分配设备 → 从缓冲管理中申请缓冲区；
3. 请求交给**设备驱动程序**：把“读1块”翻译成：**CR设命令字、MAR设内存地址、DC设字数，然后启动设备**；
4. 设备控制器指挥设备干活（可用DMA），数据**设备→内存**直传；
5. 完成后设备/控制器发**中断**，进入**中断处理程序**：保存现场→识别中断→善后（数据已到缓冲区）→**唤醒等待的进程**→恢复现场；
6. 被唤醒的进程从缓冲区取走数据，`read` 返回。

3. **“保存现场、处理中断、唤醒进程” → 中断处理程序**。

## 5.5 应用程序I/O接口（低频考点，知道概念即可）

操作系统给应用程序提供三类设备接口：

| 接口类型 | 面向 | 说明 |
| --- | --- | --- |
| **块设备接口** | 磁盘、光盘等 | 以“块”为单位，支持随机访问：read block / write block |
| **字符设备接口** | 键盘、打印机等 | 以“字符/字节”为单位，顺序访问，通常有行缓冲 |
| **网络设备接口（socket）** | 网卡 | 以“报文/包”为单位通信，面向连接的流或数据报 |

**阻塞I/O vs 非阻塞I/O**（一句话概念题，低频）：

- **阻塞I/O**：进程发出I/O请求后**挂起等待**，直到I/O完成才被唤醒——“我等你办完，你回来我再走”；
- **非阻塞I/O**：进程发出I/O请求后**立即返回**，继续执行其他任务，之后通过查询或中断获得结果——“我顺手把活交给你，你先办着，我忙别的”。

> 软考点：“阻塞I/O会进入阻塞态”（✓）；“非阻塞I/O = 不产生中断”（✗，非阻塞只说明进程不等待，设备完成后仍可能中断通知）。

## 5.6 缓冲区管理（重点，含必考计算）

### 5.6.1 为什么需要缓冲：四个“矛盾”（简答题素材）

1. **缓和CPU与设备速度矛盾**：CPU快、设备慢，缓冲把“快慢不同步”变成“中间先存着”；设备往缓冲填数据时，CPU照常干活；
2. **减少中断频率**：把“每字中断”变成了“装满一批/处理完一块才中断”（缓冲区大小与中断频率成反比）；
3. **解决数据粒度不匹配**：设备送出的是“字节流”，程序要的是“块/记录”，缓冲负责拼装拆解；
4. **提高CPU与设备并行性**：设备传第2块时，CPU并行处理第1块——这就是单/双缓冲的核心思想。

### 5.6.2 单缓冲与双缓冲：T、M、C 三大阶段

先定义三个时间（考题就是它们）：

| 符号 | 含义 |
| --- | --- |
| **T** | 设备把数据**输入缓冲区**的时间（填缓冲，T） |
| **M** | 把数据从缓冲区**拷贝到工作区（用户区）**的时间（传送，M） |
| **C** | **CPU对工作区数据加工处理**的时间（处理，C） |

![5-8 单缓冲与双缓冲工作示意](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-08_single_double_buffer.png)

*图5-8 单缓冲：只有一个缓冲区，设备填下一块必须等“拷贝M”结束——T2与C1可并行，但T2与M1串行；双缓冲：两个缓冲轮换接力，T2不必等C1。下部时间轴标注稳态周期公式。*

**单缓冲**（一个缓冲区）：

- 流程：`设备填缓冲区(T) → 缓冲→工作区(M) → CPU处理(C)`；
- **关键约束**：只有1个缓冲区，所以**第2次输入（T2）必须等第1次拷贝（M1）结束后**才开始；但**T2 与 C1 可以并行**；
- 结论：**处理一块的时间 = max(C, T) + M**。

**双缓冲**（两个缓冲区轮流）：

- 设备填缓冲1时，CPU可处理缓冲2中的数据，两缓冲**交替接力**；
- 关键约束：**第2次输入（T2）不必等C1结束**（缓冲2是空闲的）；
- 结论：**处理一块的时间 = max(C + M, T)**。

> 推导口诀：单缓冲像“单人食堂”——给你打饭（T）只能等上一个吃完（M完成）才开始；双缓冲像“两个窗口”——排队打饭不用等上一份吃完。每个公式里的“M”都来自“拷贝”这一小段时间。

#### 深化学习：n 块连续处理的两张时间轴

公式记住了，但"为什么"要靠时间轴。看单缓冲流水线如何转起来：

![5-19 单缓冲n块时间轴](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-19_buffer_n_blocks.png)

*图5-19 单缓冲逐块流水（T=120、M=20、C=80）：首块 T+M+C=220μs，其后每块进入稳态 max(C,T)+M=140μs。*

![5-20 双缓冲时间轴](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-20_double_buffer_timeline.png)

*图5-20 双缓冲流水：填缓冲2与处理缓冲1并行，每块 max(C+M,T)=120μs，设备全程不停歇。*

**两张图读出的三个考点**：

- **单缓冲公式的适用前提是"稳态流水"**：只处理 1 块时时间 = T+M+C（220μs），不是 max(C,T)+M；连续 n 块才是"首块全流程 + (n−1)×稳态"；
- **双缓冲省在哪**：单缓冲时"填缓冲"与"取走（M+C）"必须交替占同一缓冲；双缓冲一填一取两不误——**T 与 C+M 并行**，谁慢听谁的（max）；
- 【自测】T=100、M=20、C=50，双缓冲每块 = max(50+20, 100) = **100μs**；若 C=150 → max(170,100) = **170μs**（瓶颈换到 CPU 侧）。

### 5.6.3 循环缓冲（in/out 双指针）

多个缓冲区**首尾相接成环**，输入进程（生产者）和计算进程（消费者）共用，用**两个指针**协调：

- **in 指针**：指向输入进程**写满一处**后要前进的位置；
- **out 指针**：指向计算进程**读走一处**后要前进的位置；
- **in == out**：缓冲区要么**全空**、要么**全满**（其他时刻有一个“活动区”）；
- **in 落后于 out**：有数据可取；**in 追上 out**：缓冲区满，输入进程等待（同步）。

![5-9 循环缓冲与缓冲池](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-09_circular_buffer.png)

*图5-9 上半：循环缓冲（缓冲0→1→2→3→0成环，in/out两指针）；下半：缓冲池（emq/inq/outq三队列 + 收容输入/提取输入/收容输出/提取输出四种工作缓冲）。*

**【记忆口诀】** 循环缓冲 = “旋转餐厅的传送带”：厨师（输入进程）把菜放上传送带（in前进），顾客（计算进程）拿走（out前进），**in追上out = 没菜了，顾客等；out追上in = 菜摆满了，厨师停。**

### 5.6.4 缓冲池

循环缓冲只适合“**一个生产者 + 一个消费者**”；系统级I/O往往有多个设备、多个进程，于是把**所有缓冲区统一管理**成**缓冲池**：

- **三种队列**：
  - **emq：空缓冲队列**（所有空闲缓冲）；
  - **inq：输入队列**（已装满数据、等待计算的缓冲）；
  - **outq：输出队列**（已装满输出数据、等待输出的缓冲）；
- **四种工作缓冲（角色）**：**收容输入**（从设备收数据→装满→挂入inq）、**提取输入**（从inq取出→交给CPU处理）、**收容输出**（CPU结果→装入缓冲→挂入outq）、**提取输出**（从outq取出→送往设备）。

> 本质思想：缓冲区本身只有“空/满”两种身份，靠**排队状态转移**完成一切流动；“角色”随队列变化——从emq借来的空缓冲，收容输入后变“输入缓冲”，提取输入后回到emq。

### 5.6.5 【必做例题】单缓冲/双缓冲时间计算（T=120μs，M=20μs，C=80μs，n=10块）

**题目**：有一磁盘块设备，向缓冲区送一块数据需 **T = 120μs**；缓冲区向工作区拷贝需 **M = 20μs**；CPU处理一块需 **C = 80μs**。现要处理 **n = 10 块**数据，问：单缓冲、双缓冲下，处理一块的平均时间与处理10块的总时间各是多少？（假设工作区初始空闲、设备初始空闲）

**第一步：单缓冲逐块推演（时间轴验算）**

约束只有两条：① 缓冲区只有1个 → 第 i+1 次输入 `T(i+1)` 最早只能在第 i 次拷贝 `M(i)` 结束后开始；② 工作区只有1个 → 第 i+1 次拷贝 `M(i+1)` 必须等第 i 次处理 `C(i)` 结束（CPU忙）且 `T(i+1)` 完成。逐块排时间（μs）：

| 块 | T（设备→缓冲） | M（缓冲→工作区） | C（CPU处理） | C结束时刻 |
| --- | --- | --- | --- | --- |
| 1 | 0 ~ 120 | 120 ~ 140 | 140 ~ 220 | 220 |
| 2 | 140 ~ 260 | 260 ~ 280 | 280 ~ 360 | 360 |
| 3 | 280 ~ 400 | 400 ~ 420 | 420 ~ 500 | 500 |
| 4 | 420 ~ 540 | 540 ~ 560 | 560 ~ 640 | 640 |
| 5 | 560 ~ 680 | 680 ~ 700 | 700 ~ 780 | 780 |
| 6 | 700 ~ 820 | 820 ~ 840 | 840 ~ 920 | 920 |
| 7 | 840 ~ 960 | 960 ~ 980 | 980 ~ 1060 | 1060 |
| 8 | 980 ~ 1100 | 1100 ~ 1120 | 1120 ~ 1200 | 1200 |
| 9 | 1120 ~ 1240 | 1240 ~ 1260 | 1260 ~ 1340 | 1340 |
| 10 | 1260 ~ 1380 | 1380 ~ 1400 | 1400 ~ 1480 | **1480** |

**结果**：单缓冲处理10块总时间 = **1480μs**；平均每块 ≈ 148μs。

**看规律（边界效应！）**：
- **首块**：0→220μs = T + M + C，三段全部串行，无任何并行；
- 从第2块起进入**稳态**：相邻两个“拷贝起点”间隔 = 140μs（例如M2起点260、M3起点400、M4起点540……），即 **每块 = max(C,T) + M = max(80,120) + 20 = 140μs**；
- **末块**：C10从1400干到1480——它没有“下一块”可以和它并行，所以要 **再 + C = 80μs**（这就是“边界效应”：首块加T，末块加C）。

**推导公式（记这个，别死算）**：

```
单缓冲：处理一块 = max(C,T) + M
        处理 n 块总时间 = T + M + C + (n-1)·[max(C,T)+M]
                       = n·[max(C,T)+M] + min(C,T)
验证：n=10 → 120 + 20 + 80 + 9×140 = 220 + 1260 = 1480 μs ✓
```

> 【易错】`max(C,T)+M` 是**稳态流水**下“每块”的周期，不能直接 ×n 当总时间——必须把首块的T和末块的C的“边界项”处理掉。本题若有人答 10×140=1400μs，就是漏掉了首块+末块的边界项（正确应再加 min(C,T)=80μs）。

**第二步：双缓冲逐块推演**

两个缓冲 B1/B2 轮流；T(i+1) 从第2块起在“上一个T结束、对应缓冲空闲”时立即开始（缓冲有2个，几乎无缝）。逐块排时间：

| 块 | 入缓冲 | T | M | C | C结束时刻 |
| --- | --- | --- | --- | --- | --- |
| 1 | B1 | 0 ~ 120 | 120 ~ 140 | 140 ~ 220 | 220 |
| 2 | B2 | 120 ~ 240 | 240 ~ 260 | 260 ~ 340 | 340 |
| 3 | B1 | 240 ~ 360 | 360 ~ 380 | 380 ~ 460 | 460 |
| 4 | B2 | 360 ~ 480 | 480 ~ 500 | 500 ~ 580 | 580 |
| 5 | B1 | 480 ~ 600 | 600 ~ 620 | 620 ~ 700 | 700 |
| 6 | B2 | 600 ~ 720 | 720 ~ 740 | 740 ~ 820 | 820 |
| 7 | B1 | 720 ~ 840 | 840 ~ 860 | 860 ~ 940 | 940 |
| 8 | B2 | 840 ~ 960 | 960 ~ 980 | 980 ~ 1060 | 1060 |
| 9 | B1 | 960 ~ 1080 | 1080 ~ 1100 | 1100 ~ 1180 | 1180 |
| 10 | B2 | 1080 ~ 1200 | 1200 ~ 1220 | 1220 ~ 1300 | **1300** |

**结果**：双缓冲处理10块总时间 = **1300μs**；平均每块 = 130μs。

看规律：从第2块起，设备连续灌入（T的结束时刻：240、360、480……间隔120μs），即 **每块 = max(C + M, T) = max(80+20, 120) = 120μs**；总时间 = T + (n−1)×120 + (M+C) = 120 + 1080 + 100 = **1300μs**。等价于 n×120 + min(C+M, T) = 1200 + 100 = 1300μs ✓。

```
双缓冲：处理一块 = max(C+M, T)
        处理 n 块总时间 = T + (n-1)·[max(C+M,T)] + (M+C)
                       = n·[max(C+M,T)] + min(C+M,T)
验证：n=10 → 120 + 9×120 + 100 = 1300 μs ✓
```

![5-10 缓冲计算例题时间轴](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-10_buffer_calc.png)

*图5-10 T=120μs、M=20μs、C=80μs、n=10块的完整时间轴：上为单缓冲（总1480μs），下为双缓冲（总1300μs）；红色竖线标出首块边界与结束时刻，橙色横线标出稳态周期。*

**结论对比**：双缓冲比单缓冲快 1480 − 1300 = **180μs**（≈1.3块的时间），本质是双缓冲让**设备不再等CPU**，把“设备等”的时间几乎都吃回来了。

**【考点·变形】** 若题目给“每块1KB，设备速度……”把T换算成时间即可；若题目问“每秒能处理多少块”，就用 `1/每块时间` 计算——单缓冲 ≈ 1(秒)/140μs ≈ 7143 块/秒。

【真题风格例题】单缓冲，T=100μs，M=10μs，C=50μs，n=4块：总时间 = 100+10+50 + 3×(100+10) = 160+330 = **490μs**（用公式 n×110 + min(50,100) = 440+50 = 490 ✓）。请以上面10块的例题为模板，换数字套公式即可。

## 5.7 设备分配：先查表，再分配，一生只爱一台设备

设备分配回答一个问题：**用户请求一台设备时，系统把哪台具体设备分给哪个进程？** 答案藏在四张"账本"里。

### 5.7.1 设备分配中的数据结构（四张"账本"）

![5-11 设备分配数据结构与流程](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-11_device_tables.png)

*图5-11 上层：SDT→DCT→COCT→CHCT四级数据结构；中部：六步分配流程（③⑤失败则挂入对应等待队列）；底部：安全分配 vs 不安全分配。*

| 数据结构 | 存什么 | 一句话 |
| --- | --- | --- |
| **SDT 系统设备表** | 系统中所有设备类、每类设备数量、设备控制表的入口地址 | 第一张“总目录” |
| **DCT 设备控制表** | 设备类型、设备标识、设备忙闲状态、设备物理地址、等待队列、指向COCT | 每个设备一张“个人档案” |
| **COCT 控制器控制表** | 控制器标识、控制器状态、请求队列、指向CHCT | 控制器“排班表” |
| **CHCT 通道控制表** | 通道标识、通道状态、请求队列 | 通道“排班表” |

> 【记忆口诀】**“系（统）—设（备）—控（制器）—通（道）”**：从大到小、从总到分：SDT管“有什么设备类”，DCT管“某台设备闲不闲”，COCT管“哪个控制器可用”，CHCT管“哪条通道可用”。没有通道的简单系统可省去CHCT。

### 5.7.2 分配流程（务必能背下这六步）

1. **进程以逻辑设备名提出I/O请求**；
2. 查 **SDT** → 定位到具体设备的 **DCT**（检查设备是否可共享、是否空闲）；
3. **设备空闲吗？** 否 → 进程挂入**设备等待队列**并阻塞；是 → 分配给该进程；
4. 继续申请**控制器COCT**，再申请**通道CHCT**（逐级申请，逐级检查）；
5. **控制器/通道都空闲吗？** 否 → 挂入对应等待队列；是 → 分配成功；
6. **分配成功**：设备置“忙”、建立**逻辑设备名→物理设备名映射（写入LUT）**、启动I/O；I/O完成后**中断处理程序善后并逐级释放**（通道→控制器→设备，置空闲，唤醒队首等待者）。

> 【考点】**分配时“从大到小找”：SDT→DCT→COCT→CHCT；释放时反序**。且"先申请者先得"，独占设备**一次只能分配给一个进程**，直到释放。

### 5.7.3 安全分配 vs 不安全分配（高频判断）

| 对比项 | **安全分配方式** | **不安全分配方式** |
| --- | --- | --- |
| 做法 | 进程发出I/O请求后**立即被阻塞**，直到I/O完成才被唤醒 | 进程发出I/O请求后**仍可继续运行**，需要时可继续申请其他设备 |
| 死锁风险 | **不会死锁**（一次只申请一台设备，破坏了“请求并保持”条件） | **可能死锁**（可持有设备继续申请别的设备→循环等待） |
| 优点 | 简单、绝对不会死锁 | 设备利用率高、CPU与设备并行度高 |
| 缺点 | 效率低：设备与CPU基本串行，吞吐低 | 需要配合死锁检测/预防/避免 |
| 适用 | 低速独占设备 | 高速设备、追求吞吐的系统 |

**【易错·考点】** 安全分配 ≠ “不会发生任何问题”，它只保证**无死锁**；它牺牲了并行性。不安全分配 ≠ “一定死锁”，只是**有死锁风险**——考题若问“防止死锁”，安全分配是答案；若问“提高利用率”，不安全分配是答案。

【真题风格例题】判断题：“采用安全分配方式时，进程发出I/O请求后必须立即阻塞。”（√）

【真题风格例题】判断题：“不安全分配方式一定会导致死锁。”（✗——只是可能死锁，需配合死锁处理策略。）

#### 深化学习：安全 vs 不安全的一图对照

![5-21 安全与不安全分配](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-21_safety_alloc.png)

*图5-21 安全分配：发请求即阻塞（破坏"请求并保持"，不死锁但串行）；不安全分配：继续运行可再申请（高效但可能死锁）。*

**图后解读要点**：

- **为什么"安全"**：阻塞后进程**手里不持有**旧设备资源，"请求并保持"被结构性破坏——死锁四条件缺一，永不死锁；
- **为什么"不安全"仍被采用**：现代系统配合**死锁避免/检测**（银行家、资源分配图）来兜底风险，换取高吞吐；
- 【关联记忆】这是第 2 章"死锁预防 vs 避免"在设备管理中的实例：安全分配 ≈ 预防（静态保守），不安全分配 + 银行家 ≈ 避免（动态风控）。

## 5.8 SPOOLing（假脱机）技术：把“独占设备”变成“共享设备”（重点）

### 5.8.1 问题背景

打印机是**独占设备**（一次只能一个进程用）。要是一台打印机被进程A霸占打印1000页，进程B只能干等——操作系统既不想让用户装10台打印机，又想让所有人“都有一台打印机”，于是发明了**SPOOLing（Simultaneous Peripheral Operations On-Line，假脱机）**。

**核心思想**：在磁盘上划出**输入井/输出井**，把“要打印的数据”先**存进磁盘**（不再直接占用打印机），然后由一个管理程序**分期分批**地模拟打印机输出——用户感觉不到别人在排队，仿佛独占了一台打印机。

### 5.8.2 结构：四张“牌”

![5-12 SPOOLing系统结构](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-12_spooling.png)

*图5-12 SPOOLing结构：用户进程只与“井”打交道（①写输出井②登记请求）；输出进程按队列从输出井取数据（③④）经输出缓冲区（⑤）逐块打印机输出（⑥）；上行虚线为输入通路。*

| 组成部分 | 位置 | 作用 |
| --- | --- | --- |
| **输入井 / 输出井** | **磁盘**上的预留存储区 | 存放用户作业的输入数据/输出数据（排队缓冲池） |
| **输入/输出缓冲区** | **内存** | 衔接井与通道（设备）之间数据进出的中转 |
| **输入/输出进程** | 内存常驻（或由通道实现） | ①把设备输入的数据送到输入井；②把输出井数据按队列送到设备 |
| **井管理程序** | 核心管理代码 | 协调以上各部分：接收请求、管理队列、调度井的读写 |

**以“共享一台打印机”为例的工作流程**：

1. 用户进程提交打印请求 → 系统把打印数据**写入输出井**（磁盘），并把请求挂入**请求队列**；
2. 用户进程立即返回，继续做自己的事——**它觉得打印机已归自己**；
3. **输出进程（井管理程序）**从请求队列取出一个请求；
4. 输出进程**从输出井读出**该任务的数据；
5. 数据送入**输出缓冲区**（内存）；
6. 打印机按排队顺序**逐块打印**（设备真正的输出动作）；打印完释放打印机，处理下一个请求。

### 5.8.3 两大作用（背诵级）与考点

1. **把独占设备改造成共享设备（假脱机）**：逻辑上每个用户“独占”打印机，物理上多进程分时排队使用——**逻辑独占、物理共享**；
2. **缓和CPU与设备速度矛盾、提高CPU与设备并行度**：用户“打印”的过程本质只是往磁盘写数据（快），真正的慢速打印由输出进程在后台慢慢做。

**【易错·考点清单】**：
- SPOOLing 需要**磁盘空间**（井）作为代价，**不属于内存管理**、也不改变“打印机是独占设备”的物理本质；
- 多进程“同时打印”≠ 真正同时：打印机仍然**分时使用**，只是用户无感知；
- SPOOLing 的“输入进程”对设备来说像一台“虚拟设备”——考题常问“SPOOLing是否实现了对独占设备的共享”答案**是**（逻辑上的）；
- **作业管理**与SPOOLing：作业的输入输出通过“井”进行，也常用于批处理系统中。

【真题风格例题】判断题：“SPOOLing技术使得打印机的物理共享成为可能，因此多个进程可以真正同时向打印机输出。”（✗——物理上仍分时，是“逻辑上独占、物理上分时共享”。）

【真题风格例题】选择题：SPOOLing系统实现“假脱机”的关键设备是（ ）
A. 磁盘　　B. 内存　　 C. 打印机　　D. 通道
解析：**A**。输入井/输出井位于磁盘，正是“先入井、后按序输出”的“假脱机”本质。

#### 深化学习：从时间轴看 SPOOLing 的"假独占"

![5-22 SPOOLing打印时间轴](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-22_spooling_print_timeline.png)

*图5-22 三个用户进程"同时"打印的时间轴：0~80μs 大家都"申请成功"（各自占了一块输出井盘块）；100μs 起物理打印机按队列逐份真打印。*

**图后解读要点**：

- **"虚拟"的准确含义**：每个用户进程拿到的是**输出井里的一块磁盘空间 + 一个排队号**——"逻辑上独占、物理上排队"，这就是"把独占设备改造为共享设备"的全部秘密；
- **代价清单（简答题）**：占用磁盘（井）、占用内存（缓冲区与输入/输出进程）、打印可能延迟——典型"用空间与间接换并发"；
- 【易错】"SPOOLing 后打印机可以同时为多个用户打印" → **错**！物理打印机任何时刻只出一份纸；"共享"发生在**逻辑层**。

## 5.9 设备独立性与逻辑设备表 LUT

### 5.9.1 为什么需要设备独立性

如果程序里写死“用LPT1打印”，系统换了打印机就崩。**设备独立性**（设备无关性）就是：**应用程序使用逻辑设备名（如“打印机”），由操作系统负责与具体物理设备（LPT1）对接**。好处：

1. 应用程序独立于物理设备——换设备、增设备**不改程序、不需重编译**；
2. 便于设备的**统一管理、分配、调度与共享**；
3. 系统可灵活地把逻辑设备映射到不同物理设备（**I/O重定向**）。

### 5.9.2 逻辑设备表 LUT（Logical Unit Table）

LUT存放**逻辑设备名 → 物理设备名**的映射（也可能直接映射到设备控制表DCT）。有两种设置方式：

![5-13 逻辑设备表LUT与I/O重定向](/Users/levi/IdeaProjects/操作系统/第5章_输入输出管理/figures/ch5-13_lut.png)

*图5-13 上：逻辑设备概念链（程序→逻辑名→LUT→物理名→SDT/DCT）；中：全系统一张LUT vs 每用户一张LUT；下：I/O重定向的本质=修改LUT映射。*

| 对比项 | **方式A：全系统一张LUT** | **方式B：每用户（进程）一张LUT** |
| --- | --- | --- |
| 做法 | 所有用户共用一张表 | 为每个用户/进程建立一张表（登录或进程创建时建立） |
| 特点 | 逻辑设备名**全局唯一**，系统只需一张表 | 不同用户可定义**同名**逻辑名，映射到不同物理设备 |
| 优点 | 实现简单、占用空间小 | 灵活：用户可定制、“我的打印机”和“你的打印机”互不冲突 |
| 缺点 | 不灵活：用户不能用自己的逻辑名/映射 | 每用户一张表，占用空间；需随进程维护 |

**I/O重定向**（一句话）：**重定向 = 修改逻辑设备表中“逻辑名→物理名”的映射**。例如 shell 命令 `ls > out.txt`：程序里输出到“标准输出（显示器）”，系统把“标准输出”改映射到文件 out.txt，输出就全进文件了——程序一行没改。

【真题风格例题】判断题：“设备独立性意味着应用程序可以随意指定物理设备号。”（✗——独立性恰恰是**不指定物理设备**，只使用逻辑设备名。）

## 三、易错点清单（≥8条，条条踩过坑）

1. **DMA ≠ CPU完全不参与I/O**：初始化（设CR/MAR/DC）和完成善后（处理中断）仍由CPU做；只是搬运数据不经过CPU。✓（极易错）
2. **通道中断 ≠ 设备中断**：通道完成**一批**数据才中断CPU一次；设备层的完成交给通道处理。
3. **缓冲公式 max(C,T)+M / max(C+M,T) 是“每块”稳态周期**：算n块总时间必须处理首块（+T端）和末块（+C端）的边界效应：`总时间 = T+M+C+(n−1)×每块时间`（单缓冲），不要直接 `每块时间×n`。
4. **“设置设备寄存器值”属于设备驱动程序层**，不是设备独立性软件层——寄存器翻译是驱动的事。
5. **“缓冲管理”属于设备独立性软件层**，不是驱动程序层——缓冲是通用的管理职能。
6. **块设备≠都能随机访问**：磁带是块设备，但只能顺序访问；“可寻址”与“可随机访问”不要混为一谈。
7. **SPOOLing把独占设备“逻辑上”改造成共享设备**：物理上仍是分时使用；且SPOOLing需要**磁盘**上的井，不是纯内存方案。
8. **安全分配方式说“不会死锁”**，但它一次只让进程占一台设备，效率低；不安全分配才**可能**死锁。（别把两个词的意思记反！）
9. **内存映射I/O（统一编址）占用内存地址空间**；独立编址不占内存空间但需要专门IN/OUT指令——别把优缺点张冠李戴。
10. **循环缓冲中 in==out 可能是“全空”也可能是“全满”**，需要额外的状态标志位区分；绝不能笼统说“in==out=空”。

## 四、真题风格例题（含详解，全都要做）

**例1（控制方式判断）** 下列说法错误的是（　）
A. 程序直接控制方式中，CPU必须通过反复查询状态寄存器来等待设备就绪
B. 中断驱动方式中，每完成一个字（字节）的传输就产生一次中断
C. DMA方式中，数据传输过程中CPU完全不需要介入
D. 通道方式中，通道执行通道程序来控制I/O

解析：**C**。DMA传送期间CPU不搬数据，但**初始化与结束善后仍需CPU**，“完全不需要介入”绝对化即错。其余正确。

**例2（控制方式判断）** 某系统采用中断驱动方式处理键盘输入，若键盘每秒输入100个字符，系统每处理一个字符的中断服务程序需耗时20μs（含保存/恢复现场），则中断处理占用CPU的比例约为（　）
A. 0.2%　　B. 2%　　C. 20%　　D. 100%
解析：**A**。每秒中断100次，总中断开销 = 100 × 20μs = 2000μs = 2ms；1秒=1000ms，占比 2/1000 = **0.2%**。（由此可见：字符设备中断开销小；若换成每字中断且数据量大，比例会急剧上升。）

**例3（缓冲计算）** 设设备输入一块数据到缓冲区需T=120μs，缓冲区→工作区传送需M=20μs，CPU处理一块需C=80μs。采用**双缓冲**处理10块数据的总时间约为（　）
A. 1300μs　　B. 1480μs　　C. 1400μs　　D. 1500μs
解析：**A**。双缓冲每块=max(C+M,T)=max(100,120)=120μs；总时间=120+9×120+100=**1300μs**（若选B说明把单缓冲147?——1480μs当成双缓冲，注意区分；选C 1400μs是错把稳态周期×n）。

**例4（缓冲计算）** 承上题，若改为**单缓冲**，则处理10块的总时间为（　）
A. 1300μs　　B. 1480μs　　C. 1500μs　　D. 1600μs
解析：**B**。单缓冲每块=max(C,T)+M=140μs；总时间=120+20+80+9×140=**1480μs**。熟记公式：`T+M+C+(n−1)×[max(C,T)+M]`。

**例5（层次归属判断）** 下列功能中不属于“设备独立性软件”的是（　）
A. 设备分配　　B. 缓冲管理　　C. 将抽象命令翻译为对设备寄存器的读写　　D. 逻辑设备名→物理设备名映射
解析：**C**。C是**设备驱动程序**的职责（“翻译成寄存器读写”=驱动）；A、B、D全是设备独立性软件层。

**例6（层次归属判断）** 中断处理程序的最主要任务是（　）
A. 设置设备寄存器值并启动设备
B. 保存现场、识别中断来源、完成I/O后善后并唤醒进程
C. 为用户提供printf等库函数
D. 管理输入输出井
解析：**B**。A是驱动程序；C是用户层；D是SPOOLing/设备独立性软件管理部分。

**例7（DMA细节）** DMA控制器中，用来指示“一块是否传完”的寄存器是（　）
A. CR　　B. MAR　　C. DC　　D. DR
解析：**C**。DC（数据计数器）每传一个字自动减1，**减到0表示一整块传完**，此时DMA向CPU发中断。MAR指示内存地址（自动加1）；CR存命令；DR是数据缓冲。

**例8（SPOOLing概念）** 关于SPOOLing系统，下列说法正确的是（　）
A. 它把独占设备改造成了物理上的共享设备
B. 它需要磁盘空间来存放输入井和输出井
C. 它要求打印机必须支持随机访问
D. 它只能在批处理系统中使用
解析：**B**。SPOOLing的“井”在磁盘上；“物理共享”是错的（物理上仍分时，逻辑上共享）；打印机是字符设备不要求随机访问；SPOOLing也可用于分时系统，D错。

**例9（设备分配综合）** 设备的分配流程中，正确的查找顺序是（　）
A. CHCT→COCT→DCT→SDT
B. SDT→DCT→COCT→CHCT
C. DCT→SDT→COCT→CHCT
D. SDT→COCT→DCT→CHCT
解析：**B**。分配从“总”到“具体”：先系统设备表（有什么），再设备控制表（哪台设备），再控制器、通道；**释放时反向**。

**例10（考点辨析）** 下列哪一项属于“安全分配方式”的特征（　）
A. 进程发出I/O请求后继续运行
B. 设备利用率低但不会死锁
C. 可能产生死锁
D. 必须与死锁检测配合使用
解析：**B**。安全分配＝请求后立即阻塞＝设备利用率低但**不可能**发生死锁；“继续运行”“可能死锁”“死锁检测配合”都是**不安全分配**的特征。

**例11（编址方式辨析）** 某系统I/O端口与内存单元统一编址，这意味着（　）
A. CPU必须使用IN/OUT指令访问端口
B. 端口地址完全可以等同于内存地址，不会产生冲突
C. 端口可以用普通内存指令访问，但占用内存地址空间
D. 端口地址空间独立于内存并更大
解析：**C**。统一编址=端口用内存指令访问+占内存地址空间（这就是它的缺点）；A是独立编址；B“完全等同”错误；D是独立编址的描述。

**例12（单缓冲变式）** 某文件有n块，采用单缓冲方式读取，已知T=60μs，M=10μs，C=30μs，则其处理n块的总时间为（　）（用公式表示）
解析：每块=max(30,60)+10=70μs；总时间=60+10+30+(n−1)×70 = **70n+30** μs。（检验n=1：100=60+10+30 ✓；n=4：310=100+210 ✓）

**例13（双缓冲·扩写新增）** 双缓冲，T=120μs、M=20μs、C=80μs，连续处理 10 块的总时间？
解：每块 = max(C+M, T) = max(100, 120) = **120μs**；首块也要等 T 完成（流水从 T 起步）：总时间 ≈ T + M + C + (n−1)×120 = 220 + 9×120 = **1300μs**。（对比单缓冲 1480μs——双缓冲把稳态从 140μs 压到 120μs。）

**例14（层次归属综合·扩写新增）** "①把逻辑设备名翻译为物理设备名；②设置设备控制器的状态寄存器；③缓冲管理；④检查用户I/O请求的合法性"——各属 I/O 软件哪一层？
解：① **设备独立性软件**（逻辑→物理映射）；② **设备驱动程序**（写寄存器是驱动的标志动作）；③ **设备独立性软件**（缓冲管理是这层的公共职能）；④ **设备独立性软件**（系统调用入口处的参数/权限检查）——②是驱动层唯一答案，①③④都属设备独立性软件层，靠"换台设备还一样吗"区分。

12. 双缓冲方式下每块处理时间 max(C+M, T) 成立的前提是（　）
　A. 只处理 1 块　B. 连续处理多块（稳态流水）　C. 设备速率极低　D. 无需中断
13. SPOOLing 系统中"输入井/输出井"位于（　）
　A. 内存　B. 磁盘　C. 通道　D. 控制器寄存器

**答案与简析**（先自己做，再看）：
1. **C**。打印机按字符传输、**不可寻址**，是标准字符设备；磁盘/光盘是块设备可寻址。【易错】磁带是块设备，但只能顺序访问，勿与"字符设备不可寻址"混为一谈。
2. **B**。轮询=忙等，CPU被占死；它是四种方式里最原始、无需额外硬件的。
3. **B**。DMA控制器内部经DR完成设备↔内存直传，不经过CPU的寄存器。
4. **A**。通道自己执行通道程序；CPU只需给它通道程序首地址（初始化），其余全部由通道完成。
5. **C**。A、B、D均属设备独立性软件层（管理功能）；"翻译成寄存器操作"是驱动程序。
6. **C**。每块 = max(C,T)+M = max(40,100)+20 = **120μs**；总时间 = T+M+C+(n−1)×120 = 160 + 4×120 = **640μs**（或 n×120+min(C,T) = 600+40 = 640μs ✓）。
7. **B**。inq=输入队列（装满等待处理）；emq=空缓冲队列；outq=输出队列。
8. **A**。SPOOLing：逻辑上（用户感觉）独占，物理上分时共享。
9. **B**。重定向=改LUT中逻辑设备名的映射到另一物理设备/文件。
10. **A**。安全分配=请求后立即阻塞直到I/O完成，破坏"请求并保持"，避免死锁。
11. **B**。中断驱动的数据路径是"设备→控制器→CPU 寄存器→内存"（过 CPU 的手）；DMA 是"设备↔内存"直传——这是两者的**根本**区别（A 两者都要控制器；C、D 都可能）。
12. **B**。max(C+M,T) 是**稳态流水**下的每块时间；只处理 1 块时 = T+M+C（没有可并行的下一块）。此坑与单缓冲公式同源。
13. **B**。井=磁盘上的预留区域；内存里的是输入/输出**缓冲区**——"井在磁盘、缓冲在内存"是 SPOOLing 组成的经典考法。
